## ユーザーから指摘された三領域

### メッシュ・マテリアル

Material は独立したアセットとして存在するため、「マテリアル全体がメッシュと同じコンポーネント」という表現は正確ではない。一方、メッシュ形状、描画設定、マテリアル参照が Mesh コンポーネントに集中しており、操作上の責務分離は不足している。Mesh を削除すると描画設定・マテリアルの関連付けも失われる。形状と Renderer を分ける設計を検討する価値がある。

さらに、サブメッシュごとの Material スロット、使用箇所の表示、選択オブジェクトからの Material 編集導線、複製して割り当てる操作、インスタンス単位の上書き範囲の明示が不足している。Renderer が Material 参照を持つこと自体は不具合ではない。

### Play 中の Game 操作

タイトルのメニュー不動作は実際に再現した。Game のサンプルでは Space の shortcut と Confirm／Jump の action が結び付いておらず、ゲームパッド A で同等のボタン操作を起こす経路が不足していることも再現プログラムで確認した。物理ゲームパッドでの実操作は未検証。

入力有効化は Game のホバー状態に依存し、フォーカス・入力捕捉としての設計が弱い。マウスが領域外へ出る操作、ポインター固定、マウス action、右スティックについては改善が必要。Play 中の実行時オブジェクトを Hierarchy／Inspector で追跡する導線も不足している。

### GUI による UI 編集

「GUI で UI を編集できない」という断定は訂正する。選択済み UI のドラッグ移動と Ctrl+Z は実操作で動作を確認した。

ただし、未選択の START ボタンは最初のドラッグで選択だけが変わり、位置が動かなかった。二回目のドラッグで移動した。選択と移動を一続きの操作にできていない。

専用 Canvas 編集ビュー、ズーム・パン、定規、八方向のサイズ変更、回転、アンカー・ピボットの直接操作、整列・等間隔配置・スナップ・複数 UI の一括変形が不足している。非表示状態の UI は既定の編集 hit test から除外され、ゲームの初期表示状態を変更せずに編集するためのプレビュー状態も必要。

## 性能と保守性

変更のないフレームでもシーン全体を Serialize し、内部で Parse による検証も行う経路がある。Undo は全体 JSON のスナップショットを保持するため、シーン規模に比例して処理とメモリー負担が増える。

空の Transform オブジェクトによる Debug 計測（各五回平均）:

|オブジェクト数|Serialize 平均|JSON サイズ|101 スナップショットの JSON 理論合計|
|---:|---:|---:|---:|
|100|21.9 ms|14,764 bytes|約 1.49 MB|
|1,000|216.6 ms|145,264 bytes|約 14.67 MB|
|10,000|2,606.0 ms|1,468,264 bytes|約 148.29 MB|

これは Debug の限定計測であり、並行処理の影響もある。製品版の FPS や実測メモリー量を示すものではない。ただし、全体処理を毎フレーム行う設計の規模依存性は確認できる。

ほかに、定期的なアセット再帰走査と広範囲のリソース再読み込み、依存関係表示時の毎フレーム解析、大量 Hierarchy 行の描画、フォルダーツリーの反復走査、編集中の GPU 待機・再構築の頻度が調査対象となる。

Lizard はリポジトリ全体 1,141 関数のうち 70 件の複雑度警告を報告した。Editor の AnimatorPanel::Draw、ComponentPanel::Draw、Physics 表示などにも高い複雑度がある。複雑度はバグの証明ではないが、変更時の見落としを減らすための分割候補になる。

## 検証結果と限界

- 現在のソースで Debug 回帰テストを再ビルドし、実行は終了コード 0。ビルドは警告・エラー 0。
- `tests/test_scene_conversion.py`: 8 テスト成功。
- 独立した再現プログラム: シーン移動、外部変更上書き、Prefab 部分適用、Game／Title の action 接続、非表示 UI の hit test、GLB ヘッダーの七項目を確認。
- 実操作: Play のタイトルメニュー、UI 選択・ドラッグ・Undo、Material 切り替え・読み込み失敗・外部更新、シーン移動後の保存を確認。
- 全体 Cppcheck は長時間実行後に中断したため、成功扱いにしない。Editor 範囲の実行は外部ヘッダーの診断を返した。自前 Editor ソースの診断がなかったことは、不具合がない保証ではない。
- Release、物理ゲームパッド、複数モニター・高 DPI、長時間稼働、ディスク容量不足・書き込み失敗・強制終了などは未検証。
- 最後の画面操作はユーザーの Escape により停止された。停止後の画面状態・アプリ終了は確認していない。

再現用ソース・ログは ignored の `generated/editor-audit/` と `generated/analysis/` にある。一時的に作った Content アセットは削除し、既存 Content の変更は残していない。

結論として、重要な操作上の問題は複数の実再現まで進めたが、全操作・全異常系を網羅したとは言えない。データ喪失や誤保存につながる問題を最優先に、その後に Play 入力と UI 編集の操作体系を改善する。
