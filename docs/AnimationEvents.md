# アニメーションイベント

AnimatorのInspectorで、クリップ名・時刻（秒）・イベント名・数値／文字列／整数引数・最低重みを設定する。
設定はシーン保存、Undo/Redo、Prefabのプロパティ上書きに含まれる。旧形式ではイベント一覧を省略できる。
1つのAnimatorは最大256キーを保存できる。時刻はクリップの開始から終了までの範囲で指定する。

正の再生区間で通過したキーを通知する。開始時刻0のキーは最初に時計が進んだ時に1度通知し、初期プレビューでは通知しない。
ループをまたぐ更新では、通過した全ループのイベントを時刻順に取得する。境界では前のループの終了、次のループの開始の順で通知する。
同じ時刻に別のキーを置けば、それぞれを通知する。非ループの終了キーは1度だけ通知する。
キーと時計のfloat丸め差には最大1マイクロ秒の許容値を使い、次の区間で同じキーを再通知しない。
停止・無効化・速度0・ゼロ秒の評価では通知しない。

Blend Treeでは共通の位相から各クリップの時刻を求める。同じクリップが複数の子にある場合は重みを合算して、各キーを1ループに1度だけ通知する。
異なるクリップの同名イベントは個別の通知になる。最低重み、またはScriptでの重み判定を使って必要な通知を選択する。
クロスフェード中は進行している遷移先の時計を使い、通過した時点の遷移重みも反映する。
入力や重みの変更で新しく有効になったクリップに、過去のキーを再通知しない。

検出したイベントはその個体を宛先として、次のScript更新の`onEvent`へ渡す。
`context.event->name`と`value`で従来のイベントと同様に処理できる。
`context.event->animation`には元のクリップ、状態名、時刻、引数、重み、ループ番号、正規化位相、キーの番号が入る。
このメタデータがない通知は、衝突や通常のScriptイベントとして区別できる。
一時停止中は未配信の通知を保持し、コマ送りや再開で配信する。再生停止で実行状態を破棄し、編集データを維持する。

`SceneWorld::UpdateComponents`は、全個体の姿勢・イベント・Scriptの候補を検証してから反映する。
姿勢の失敗やイベント超過では、先に評価した個体、Scriptの状態、配置、生成ID、イベントキューも保持する。
通常の更新では頂点バッファーを再作成しない。イベントは通常のScript通知と合わせて、1シーンの更新につき4096件まで予約できる。
App／Editor共通の環境時計も、拒否されたComponent更新では進めない。

`Content/Assets/Scenes/AnimationEventPlayground.json`はイベントを受けて各キャラクターのライトを点滅させる。
登録済みの`AnimationEventPulse` Scriptを使用し、`duration`と`peak`で光の長さと強さを調整できる。
`scripts/GenerateAnimationEventPlayground.py`で比較シーンを再生成できる。
`WP1_ANIMATION_EVENTS_ONLY=1`で、ループ・重み・引数・保存編集・App/Editor・更新失敗時の保持を検証する。
