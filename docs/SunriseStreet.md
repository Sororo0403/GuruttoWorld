## 旧探索版（保存データを保持）

タイトルのSTARTから `Assets/Scenes/SunriseStreet.json` に入る。入口広場から、左のカフェ屋上と右の商店通りに分岐し、中庭で合流する。商店通りの箱を壊すと、部屋の中まで歩ける隠し部屋に入れる。中庭の先は可動橋と水路の飛び石、左右に曲がる植栽の道、展望塔へ続く。タイトルの朝の光、空、建物・道路・舗装素材、開始演出を引き継ぐ。

## 探索する街区

- 左ルート：10段の階段で高さ3mのカフェ屋上へ上り、屋上を歩いて、奥の階段から中庭へ降りる。手すりをジャンプすると看板の裏の小さな足場に隠した花を取れる。
- 右ルート：商店脇のアーケードを地上で通り抜ける。オレンジの箱を攻撃で壊すと、店舗裏の隠し部屋へ入れる。床、壁、入口、室内の花と家具があり、カメラから主人公が見えるよう天井を省いた構図を使う。入口から本線へ戻れる。
- 水路：歯車で中央の橋をつなぐ主ルートと、右へ寄り道して4つの足場をジャンプで渡るルートがある。寄り道の花は任意。
- 北の庭：左右交互の花壇を避けて進む。2つ目の歯車の先に展望広場がある。

屋上と隠し部屋に実際に入ると「発見」が増える。発見2か所と花12個は任意で、地上の主ルートだけでもクリアできる。再挑戦で発見もリセットする。カメラは横方向への追従を増やし、屋上では高さを補正して足元と降り口を見せる。移動操作の向きは従来どおり。

描画は区画ごとの6モデルへ統合し、実行時のオブジェクト数は147。装飾と舗装を含む元の配置を統合し、階段、壁、壊す箱、橋などの当たり判定を保持する。7種類の効果音も引き続き事前に読み込む。共通Engine・SceneRuntime・エディターへの変更はない。

## 操作と目的

| 操作 | キーボード | パッド |
|---|---|---|
| 移動 | WASD または矢印 | 左スティック |
| ジャンプ | Space | A |
| 攻撃と装置の作動 | J | X |
| 再挑戦 | R | Start |
| タイトルへ戻る | Esc | B |

ジャンプを保持すると短時間の空中停止が使える。水路手前と広場のオレンジの歯車を近くから攻撃すると装置が作動する。最初の装置は橋を中央へ移動させ、2つの装置を作動させると展望広場への柵が開く。歩いて歯車に触れるだけでは作動しない。

花のかけら12個は任意の収集目標。屋上、看板裏、隠し部屋、水路にも配置している。ライフ切れや落下では最後に通った地上のチェックポイントへ戻り、取得、発見と装置の進行を保持する。再挑戦ではステージ全体をリセットする。展望広場のオレンジのゴールでクリアとなる。

## 見た目とゲーム処理

建物、道路、歩道、歯車、空、直射光は既存タイトルの素材・設定を利用する。公園のKenney Nature Kitの木と花も利用する。新しい配色マテリアル、効果音、キャラクターの伸縮・歩行の反応を追加した。外部素材の新規取得はない。効果音はPythonの標準ライブラリで合成したオリジナル音源。

ゲーム処理は `Games/GuruttoWorld/Assets/Scripts/SunriseStreet.cpp`。既存の公園の処理と保存済みシーンは変更していない。共通エンジンの変更もない。

## 編集と検証

動く仕掛けやゲーム進行はEditorで保存済みシーンを編集する。静止した街の描画は区画ごとのモデルへまとめているため、個々の街路・建物の配置を変える場合は `scripts/AuthorSunriseStreet.py` と元モデルを編集して再生成する。このツールは専用マテリアル・音源も再作成する明示実行の制作ツールであり、通常のビルドでは実行しない。手動編集後に実行すると新ステージの配置を置き換える。タイトルの書き換えは行わない。

```powershell
python -m unittest discover -s tests -p test_sunrise_authoring.py -v
MSBuild tests/SunriseStreetValidation.vcxproj /p:Configuration=Release /p:Platform=x64 /m:1 /nr:false
generated/tests/outputs/x64/Release/SunriseStreetValidation/SunriseStreetValidation.exe
MSBuild Games/GuruttoWorld/GuruttoWorld.vcxproj /p:Configuration=Release /p:Platform=x64 /m:1 /nr:false
```

Python検証は保存データと制作ツールの一致、参照と素材、STARTの決定・クリック両経路、収集数と必須装置、階段・橋の構造を確認する。C++検証は実際のJoltキャラクターでジャンプ、階段、12個の取得、攻撃での装置作動、橋の移動、落下復帰、出口、クリア、再挑戦とタイトル復帰を確認する。描画検証では入口・テラス・水路・展望広場、およびタイトルからの入場を確認し、`generated/sunrise/previews` に保存する。

`WP1_SUNRISE_CPU_ONLY=1` で物理の検証のみ、`WP1_SUNRISE_RENDER_ONLY=1` で描画とタイトル接続のみを実行できる。自動再生の検証と人間による操作感の評価は区別する。

## 初版時点の確認結果（履歴）

- Releaseのゲーム本体とゲーム処理DLLをビルドした。この環境ではVisual Studioのデバッグ情報生成DLLのバージョン不整合を避けるため、ビルド時だけ `$env:_LINK_='/DEBUG:NONE'` を指定した。
- 新ステージのPython検証3件、公園の生成検証6件、制作データ検証4件が成功した。既存の生成検証は `PYTHONPATH` に `scripts` を指定し、一時ファイルはワークスペース内へ出力した。
- Joltによる通しプレイが2511フレームで成功した。12個の取得、階段、歯車2個、橋の移動、落下復帰、箱の破壊、クリア、再挑戦、タイトル復帰を確認した。フレーム数は自動攻略の所要量であり、人の初回プレイ時間ではない。
- タイトルのクリックをメニュー処理へ渡し、開始演出の完了後に保存先の新ステージを読み込むことを確認した。入口・テラス・水路・展望広場と、タイトルから入った最初の画面をGPUで描画した。
- Release配布物は `Games/GuruttoWorld/generated/builds/Release-20261015000000000000000000000001`。このフォルダーの `App.exe` を起動し、STARTで入場する。タイトルを起動対象とした配布検証が成功し、私有コピーでは新ステージを起動対象としてゲーム処理DLL・モデル・シェーダー・UIの読み込みと更新・描画も確認した。

人間によるキーボード・パッドの操作感と、異なる画面比率での実機確認は未実施。

配布時に既存の共通ビルドスクリプトの問題も確認した。`BuildPlayer.ps1 -Project ...` は文字列型の引数 `$Project` に設定オブジェクトを代入するため、生成した `package.json` の `startupScene` がnullになる。実際の `Assets/Project.json` と起動は正常。今回の配布物ではメタデータの値だけを実際の起動シーンへ補正し、439ファイルの配布ハッシュを照合した。共通ビルドスクリプト自体は変更していない。

## 重さの改善

新しい配布版は `Games/GuruttoWorld/generated/builds/Release-20261015000000000000000000000003`。STARTから同じステージに入る。初版で不足していた実描画を含む性能計測を行い、静的描画の統合と効果音の事前読み込みを追加した。結果と計測条件は [SunrisePerformance.md](SunrisePerformance.md) を参照。

静止した256オブジェクトの描画を6区画へまとめ、実行時の配置数は350から150へ減らした。当たり判定は元の配置・大きさ・親子関係を保持する。`scripts/SunriseBatching.py` が既存OBJとマテリアルから作り、`Assets/Models/Sunrise/Batches/Sources.json` に元モデルと統合対象を記録する。元モデルのCC0ライセンスは従来の場所に保持する。

効果音はゲーム側の7つの固定スクリプトがEngineの公開AudioSystem APIで準備し、イベントで読み込み済みの音源を再生する。プレイ中の生成・削除、AudioSourceの有効化に伴う再読み込みを行わない。音量はステージ開始時の保存設定に従い、ゲームのフォーカスを失うと効果音の出力を止める。シーン終了で音源を解放する。共通エンジン・エディターは変更していない。
