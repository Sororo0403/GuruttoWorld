# 根本設計の段階移行

本書は先行移行の履歴（段階0〜7）。後続のM0〜M7の構成・検証は [M0〜M7の実装記録](ArchitectureImplementation.md) を参照する。

## 正本と成立条件

- プロジェクトのエンジン参照・ID・コンテンツ層は ProjectContext が解決する。別チェックアウトの Editor・DLL・共有素材を暗黙に混在させない。
- 編集ドキュメントが保存データの正本。実行 World と描画資源は派生物で、Stop は編集データを変更しない。
- 同じドキュメントの保存結果は DLL のロード状態と ScriptRegistry に依存しない。既定値補完は明示的な移行として記録する。
- 内部参照は複製時に変換する。Prefab 外部参照は配置時の明示的バインディングとし、偶然一致する ID に結び付けない。
- Prefab の配列はフィールドごとにマージ単位を定義する。並べ替え可能な要素は安定 ID で対応させ、競合を診断する。
- Prefab 適用の Undo は元アセットとシーンを一緒に戻す。外部編集と競合する場合は、他の変更を上書きせず拒否する。
- Editing は実行セッションを所有しない。Play の準備失敗時はドキュメント・履歴・選択・モードを維持する。
- 実行更新のトランザクションはホスト管理のデータと予約コマンドを対象にする。任意の C++ コールバックが直接起こす外部副作用の自動復元は保証しない。音声などは成功後のコマンドへ移す。
- 欠損資源を診断として保持し、データとして妥当なドキュメントの修復・Undo を描画の成功と分離する。
- 実行中の単独・追加ロードも、新規ScriptのStartと派生資源の準備を候補上で完了してから交換する。Persistentな既存インスタンスは維持し、除去したインスタンスのStopは成功時に一度だけ呼ぶ。
- 通常の再生フレームは固定更新・Update・LateUpdateの一つの保存点を持つ。入力の準備は物理を進めず、後段の失敗では配置・物理・Script状態・固定時間蓄積とライフサイクル予約を戻す。Worldの単独更新APIを明示的に呼ぶ場合は、それぞれを独立した取引として扱う。
- シーンと未保存Materialの保存は、全対象を事前検証して同じFileTransactionで確定する。別名保存のパス・保存基準も全ファイルの成功後に更新する。プロジェクト設定も読み込み時の内容と比較し、外部変更・削除を上書きしない。
- 手続きメッシュのキャッシュは利用中のモデルを弱参照で共有する。不要になったGPU資源は送信済みコマンドの完了まで退役管理で保持し、その後に回収する。

- 終了時の配置変更は副作用を持たないprepareStopで候補に反映し、最終のScript検証・描画・UI準備を通す。交換時は旧prepareStopを新Startより前に呼ぶ。stopは読み取り専用のScriptStopContextで、確定後の解放とStart失敗の後始末だけを担う（SDK ABI 14）。
- 保存は領域単位のプロセス間排他を取得し、同期済み候補と比較対象の実体を保持する。全対象の保存前後の内容を`.wp1-transactions/*.pending`へ同期してから旧実体を退避し、候補は非上書きの改名で設置する。ドキュメント受理前に確定方針を同期し、拒否・例外時は取消方針へ戻す。プロセス終了後はプロジェクトの検証・設定読込・素材走査・次の保存より前に未完了記録を回復し、未確定なら全対象を旧版へ、確定済みなら新版へそろえる。復旧自体が中断しても再開できる。
- 復旧先が外部作成・変更されている場合は、保持した実体を`.conflict`として退避してから回復する。所有物の判定には内容と128ビットのファイルIDを併用し、同じ内容の外部ファイルも誤って削除しない。外部内容・元のパスを示す`.info.json`・保存前後のコピーは`.recovered`フォルダーに残し、ログと保存失敗の診断に保管先を示す。復旧先がロック中、記録が不正、コピーが欠落している場合は記録を保持して対象領域の次の保存・走査・設定読込を拒否する。掃除前に記録を完了名へ移し、掃除中の再起動で復旧コピー不足にならないようにする。異なる保存領域をまたぐ一括保存は排他と復旧の単位が一致しないため拒否する。
- メタデータの初回登録は同じ排他内で非上書き作成し、競合した呼出元は確定済みIDを取得する。Inspectorのインポート設定保存は読み込み時の生データと照合する。IDと外部編集済み設定を同時生成や古い画面の保存で上書きしない。
- 複数ファイルの同時公開や、非協調アプリによる保存中のパス欠落観測までは保証しない。プロセス強制終了からの回復は管理対象の子プロセステストで検証する。電源断・OS停止・記憶装置故障の耐久性は別の実機検証が必要。

上記の監査修正は`tests/ArchitectureAuditFixValidation.vcxproj`で失敗注入と再試行を検証し、`ReviewRegressionValidation`の通常回帰からも実行する。個々のAPIだけでなく、シーン遷移・フレーム・複数ドキュメント保存の外側の成功境界を比較する。

## 検証方法

`tests/ArchitectureContractValidation.vcxproj` は管理対象ソースから構築し、出力・一時アセットは `generated/tests/architecture-contracts` に限定する。
既定実行はすべての目標契約を必須とし、不成立なら失敗する。`--baseline` は基準記録専用で、未達を `KNOWN GAP` として表示する。基準記録の成功を設計移行の完了と解釈しない。
段階の検証では `--require=<契約ID>` を併用し、その契約の未達を許容しない。

元の作業ツリーのバックアップ・ハッシュ・差分は `generated/design-migration` に記録する。既存の未コミット変更を一括整形・リセット・コミットしない。

### 段階4

- Prefabの外部接続口を素材のprefabSlotsへ、個体の明示接続先をPrefabLink.externalBindingsへ分離。接続先はScriptObjectReferenceとして扱い、同じドキュメント内の個体または外側の接続口へ向ける。内部IDと口IDの衝突は拒否する。
- 新規配置では範囲外参照を自動接続せず、未接続にする。既存個体の再接続、接続解除、既存のSceneからPrefabへ保存する際の接続維持を共通APIに集約。
- 再抽出では基準と現在値を対応させ、同じ接続先を持つ異なる口も保持する。処理中の識別子領域を分け、口とScene個体が同じ文字列でも意味を混ぜない。処理中の識別子と実在IDの衝突も検証する。
