# 修辞を「歩いて読む景色」へ翻案するための再調査

2026-10-15。配布14の比較画像が伝わらないという指摘を受け、修辞の定義、視覚的注意の研究、開発者によるカメラ・レベル設計の説明を調べ直した。以下は再設計案であり、実装済みの効果や、人による検証結果ではない。配布14の記録は後半に残す。

## 結論：小物の差し替えから、知覚と行動の順序の設計へ

今回の失敗は、修辞を小物の種類・並びだけで表し、プレイヤーがそれを読む条件を設計していなかったことにある。カメラを含む空間の構成、目的の理解、見る順序、通れる場所、移動した後の確認までを一つの単位として作り直す必要がある。

設計の基本単位を次のように置く。

**目に入る → 意味が分かる → 次を予想する → 自分で進路を選ぶ → 移動後に予想を確かめる。**

これは本プロジェクトの作業用モデルで、研究で確立した一方向の認知処理モデルという主張ではない。実際には見直しや探索が往復する。「目立つ」だけで止めず、どの段階が成立しなかったかを調べるための分解である。

修辞技法の名称を知らなくても、この体験が伝わることを目指す。名称を説明して初めて植物の大小に意味が生まれる状態は、ステージ側の伝達が未成立と判断する。

## 根拠として確認したことと、その限界

### カメラは、完成した地形を追うだけの部品ではない

『星のカービィ ディスカバリー』の開発者は、自動カメラで進行方向のランドマークを意図的に見せ、地形や装飾、次に行う遊びを一緒に調整したと説明している。本作でも追従距離だけでなく、「分岐を選ぶ前に、何が同じ画面へ入る必要があるか」を設計する。[任天堂・開発者インタビュー第2回](https://www.nintendo.com/jp/interview/arzga/02.html)

Mark Haigh-HutchinsonのGDC資料は、滑らかな動き、遮蔽回避、操作意図の維持、操作基準の一貫性をカメラ設計の課題として挙げる。したがって目印を映すためでも、急回転で操作方向を乱したり、見せ場へ強制移動したりしない。[Fundamentals of Real-Time Camera Design](https://media.gdcvault.com/gdc05/slides/GD_Haigh-Hutchinson_FundamentalsReal-TimeCameraDesign.pdf)（「Camera Design Principles」「Control Reference Frame」「Camera Design Process」を参照。具体的な調整数値の根拠にはしていない）

### 明るさ・大きさだけでは、見る場所は決まらない

WolfeのGuided Search 6.0は、視覚的な際立ちだけでなく、探している対象、過去の経験、価値、景色の構造と意味を注意の誘導に含める理論である。「目立つカップ」より、「カフェを探している人が、店の手がかりとして読めるカップ」を作る必要があるという設計上の推論につながる。ゲームの最適配置を直接実証した研究ではない。[Wolfe, 2021, Guided Search 6.0](https://pmc.ncbi.nlm.nih.gov/articles/PMC8965574/)

Rosenholtzらは複雑な画像の視覚的混雑と探索成績の関係を調べている。本作では手がかりを足すだけでなく、同じ画面にある窓・屋根・看板の競合を減らす方針を採る。ただし「物を何個まで減らせばよい」という数値の根拠にはしない。[Rosenholtz, Li & Nakano, 2007, Measuring visual clutter（著者抄録を確認）](https://pubmed.ncbi.nlm.nih.gov/18217832/)

### 修辞は映像に翻案できるが、読めることは別途確かめる

McQuarrieとMickは広告の視覚的修辞を実験とインタビューで調べ、解釈や広告への態度への影響、受け手の文化的知識による違いを報告している。この研究は道案内の効果を検証していない。借りるのは「作り手の解説だけでなく、受け手が実際にどの意味を読んだかを確認する」という姿勢である。[McQuarrie & Mick, 1999, 著者公開PDF](https://dgmick.weebly.com/uploads/2/5/1/0/25106811/mcquarrie_and_mick_1999_visual_rhetoric.pdf)

### 地形・美術・動きを同じ方向へ働かせる

GDCのデザイナー本人たちのQ&Aでは、目標だけでなく周囲の地形でそれを支えること、ランドマーク、動き、音、通行可能性を組み合わせる実務が説明されている。これは制作者の経験談であり、全プレイヤーに通用する法則としては扱わない。[GDC 2018 Level Design Workshop Q&A](https://www.gamedeveloper.com/design/gdc-2018-level-design-workshop-an-expert-roundtable-q-a)

Sucker Punchの美術担当者は、『Ghost of Tsushima』の誘導する風に、草木・布・粒子が一緒に反応する仕組みと、植生の種類やテクスチャのノイズを絞る美術方針を説明している。本作へ借りたいのは、多くの物を増やすことより、景色の複数の要素が同じ意図を伝える点である。風による案内そのものを擬人法と断定はしない。[Crafting the world of Tsushima](https://blog.playstation.com/2020/07/09/crafting-the-world-of-tsushima/)

修辞の定義はBYU / Gideon O. BurtonのSilva Rhetoricaeで確認した。下記の6案は、それらの言語構造から着想した空間表現であり、元の修辞と完全に同一だと実証したものではない。

## 適用先は技法ごとに選ぶ

各技法をすべての表現手段へ無理に適用しない。主役になる表現を決め、他はその読み取りを支える。カメラは大きな近接オブジェクトを画面端に置いて塞ぐのではなく、キャラクターと判断対象が同時に見える関係を作る。

| 手段 | 設計する内容 | 判断の基準 |
|---|---|---|
| カメラ位置・向き | プレイヤーを少し片側へ置き、進行先の画面領域を空ける。角を曲がる前に次の目印を残す | 近い視点のまま、歩ける入口と目的地の関係が見えるか |
| 地形・建物 | 広場の抜け、屋根の段差、通りの向きで主題へまとまりを作る | 小物を隠しても、その場所へ行けそうと分かるか |
| 光・色・材質 | 必要な入口と背景を分離し、競合する窓や看板を落ち着かせる | カラーを外しても輪郭・明暗・空間で読めるか |
| 動き・時間 | 判断地点に入ってから一度反応し、次の対象へ動きが渡る | 見逃しても再観察できるか。全体が同時に動いていないか |
| 音 | 行き先の生活音や反応音を視覚の手がかりと一致させる | 無音でも進めるか。音だけが逆の場所へ誘っていないか |
| 操作・仕掛け | 近づく・触れることで世界が応答し、予想を確かめられる | 気づいたことが、実際にできる行動へつながるか |
| 情報の順序 | 最初に分かること、途中で隠すこと、到達後に確認することを決める | 選択に必要な情報が、選択の後にしか出ていない状態を避ける |

「目に入る」と「実際に注視した」は別である。カメラの記録だけでプレイヤーの視線を測ったとは呼ばない。

## 6技法をどの体験へ翻案するか

知名度の2・2・2という枠は発表の構成として残せる。ただし知名度は調査済みの分類ではなく、外国語名の技法も日本語で使える。珍しさと道案内の有効性は別である。

### 1. 擬人法：景色がこちらへ働きかける

原義は、人間以外へ人の性質を与えること。[Personification](https://rhetoric.byu.edu/Figures/P/personification.htm)

**主な適用先：建物の姿勢に見える形、反応のタイミング、インタラクション。**

広場の角のカフェを、一つの迎える存在として構成する。入口上の二つの窓と庇が顔として読める輪郭を作り、近づくと庇が軽く上がり、入口横の扉が迎え入れるように開く。動く物を各所へ散らさず、建物の一つの反応へまとめる。顔の可愛さだけを目標にせず、「自分への呼びかけ→そこに入れる」という意味へつなぐ。

カメラは顔と地上の入口を同時に映す。扉だけを接写してプレイヤーから操作を奪わない。反応は判断地点から見える状態で発生し、見落とした場合も近づけば再び小さく反応する。

単に旗が風で揺れるだけなら擬人法とは呼ばない。人の意図を感じるかは人による観察が必要。動きによる目立ちと擬人性を分ける比較では、同じ動きの量で顔・応答性を外した版を用意する。

### 2. 反復法：同じ見え方を、移動のリズムへする

原義の核は表現の繰り返し。[Figures of Repetition](https://rhetoric.byu.edu/Figures/Groupings/of%20Repetition.htm)

**主な適用先：通りの区間、入口の構図、繰り返す行動。**

「日なたのテラス→奥に見える青緑の入口」を一つのまとまりにし、通りを歩くと次のテラスでも同じ関係が現れる。色だけでなく、座れる場所・開いている入口・その先の明るい空間を同じ順序で繰り返す。一枚の壁の窓列を増やすより、進行して繰り返しを経験させる。

カメラは各まとまりを似た画面上の位置へ捉え、次の入口が現在の区間から見えるようにする。反復を屋上の別ルートにも付ければそちらも案内対象になるため、主経路と寄り道に同じ意味の繰り返しを無差別に使わない。

反復がただの景観模様として読まれるなら失敗。対応する入口が実際に通れることを、最初の安全な区間で確認できるようにする。

### 3. 換喩：店そのものの代わりに、その営みを見せる

原義は対象をその属性などで指すこと。[Metonymy](https://rhetoric.byu.edu/Figures/M/metonymy.htm)

**主な適用先：環境の意味、生活の痕跡、目的地の予告。**

まず目的のカフェの特徴を一度見せる。その後に店が建物で隠れても、開いた路地の入口に同じ店の食器を載せたテーブル、カウンターの一部、奥から聞こえる食器の音を見せ、カフェが続いていると推測できるようにする。壁に貼ったカップの記号だけでなく、店の活動が路地へ続く関係を作る。

カメラは食器だけを大きく映さず、テーブルと通れる路地を一緒に映す。帰結は「この壁がカフェだ」ではなく「あの通れる路地の先に店がある」。これは関連属性による翻案案で、生活音だけの誘導をすべて換喩と呼ぶわけではない。

開始時に何を探すか分からなければ、店を連想できても移動理由は生まれない。説明HUDを出さずに済ませる場合も、目的の予告や遊び上の動機は必要である。

### 4. 漸層法：物の寸法ではなく、期待の強さを段階化する

強さ・重要度が段階的に増す広義の漸層として扱う。厳密なclimaxの用語法には連鎖構造もあるため、発表ではこの採用範囲を明示する。[Climax](https://rhetoric.byu.edu/Figures/C/climax.htm)

**主な適用先：街区のスケール、視界の広がり、目的地の露出量。**

小さな路地のテラス→広い中庭のテラス→街区の主役となる屋上テラス、と空間と目的の露出を段階的に強める。同時に窓・屋根・空の抜けが主役へまとまるよう、周辺建物の輪郭も設計する。全要素を一度に強くせず、区間の進行に従って変化させる。

カメラはキャラクターの大きさを大きく変えず、向きと横への構図で上部のテラスを見せる。ワールドの寸法が増えても、遠近で小さく投影されれば強調にならない。判断地点からの実際の描画で、対象の面積・遮蔽・背景との分離を確かめる。

強さを増すほど敵・光・音まで増やすと、行きたい場所より危険地帯に見える可能性がある。どの意味を強めるかを一つに決める。

### 5. Anadiplosis：前の景色の末尾を、次の景色の始まりへ

原義は前の句などの最後の語句を、次の冒頭で繰り返すこと。[Anadiplosis](https://rhetoric.byu.edu/Figures/A/anadiplosis.htm)

**主な適用先：カメラによる構図の受け渡し、街区の接続、移動中のランドマーク。**

広場を見渡した視界の奥に時計塔Bが見える。Bを目指して角を曲がると、Bの足元が次の通りの手前に残り、その奥に温室Cが現れる。温室へ近づいた後の景色も、温室Cを手前の起点として屋上Dへつなぐ。構造は「広場A→時計塔B／時計塔B→温室C／温室C→屋上D」。

カメラの切り替わりの前後で同じランドマークを追えるようにし、別の似た物への交換で混乱させない。ここでの「句」は看板の組ではなく、一つの空間を読んで次へ移る場面に相当する。入力を続けても同じ塔との関係を保ちながら次の場所へ進める構図を探る。

毎回同じ色を置くだけなら反復との差が弱い。区間の終点が次の区間の起点となる体験と、前後の景色の区切りが必要である。帰り道や横から進んだ場合に成立するかも別に確かめる。

### 6. Anapodoton：必須の道案内から外し、採用自体を再検討する

原義は従属節から主節が予想されながら、その主節が提示されないこと。「何かが欠けている」全般の名称ではない。[Anapodoton](https://rhetoric.byu.edu/Figures/A/anapodoton.htm)

**検討する適用先：共有した期待の未完結、任意の探索。**

配布14の「枠とカップを2回見せ、次の枠を空ける」は、原義への対応が弱い。空白から方向を読み取れる根拠もない。この案をそのまま拡大しない。

もし残すなら、「呼び鈴を押すと店が応答する」経験をした後、別の店では呼びかけの音だけが始まり、期待した返答がない、といった未完結の応答で寄り道への関心を試す。ただし後から返答が出るだけなら単なる遅延になり、条件と結果を教えるだけでも原義とは一致しない。これも十分な翻案か、言語の対応を含めて再検討が必要。

空白を埋めたい好奇心と、行き先が分かることは別の成果である。この技法は現時点では採用保留とし、6枠目が必要なら目的に合う別の外国語名の修辞へ入れ替える。珍しさを理由に、成立していない対応を発表の説明で補わない。

## 最初に試す60〜90秒の街区の絵コンテ

以下の秒数は通常歩行を想定した仮置きで、制限時間や強制カメラ演出ではない。立ち止まる・逆走する・横へ寄ることを許す。六つ全部を混ぜず、まず「目的を予告し、視界を受け渡す」街区が成立するかを確かめる。

| 区間 | プレイヤーの疑問と行動 | 画面・地形・カメラで見せるもの | 次へ渡すもの |
|---|---|---|---|
| 0〜15秒：入口広場 | あそこへ行けそう。まず広場を歩く | 手前は広く横断可能。主人公を近く保ち、建物の切れ目に目的の屋上テラスを一度見せる。中央の巨大な壁で正面を塞がない | 目的地の形・色と、手前の時計塔 |
| 15〜35秒：最初の判断 | 時計塔のそばの開いた道を調べる | 正面の通りも横の寄り道も歩ける。選択前に時計塔の足元と路地の入口を同時に映す。移動しても屋上か時計塔のどちらかを追える構図にする | 前の景色の終点B |
| 35〜55秒：角の先 | さっきの塔の向こうに次の広場がある | 塔Bを画面の手前側に残し、建物の隙間から温室Cが見えてくる。横へ回るカメラの余地を地形に確保する | BからCへの接続 |
| 55〜75秒：中庭 | 店の営みが続いている。上にも行けそう | 温室Cとカフェのテラス、実際に上がれる階段を同じ構図へ。店の属性と地上・屋上の接続を見せる | 次の景色の起点Cと、登れる経路 |
| 75〜90秒：屋上手前 | 最初に見えた場所につながった | 近い視点のまま空が開く。入口からの位置関係が分かる目印を残し、到達を景色で確認できる | 目的の確認と次の街区 |

この街区では「広場が広いこと」と「次の足場が見えること」を両立させる。床の帯や小物の列で一筋のレールを描くことを主な解決にしない。進路に必要な情報がある限り、横の遊びを選んでも迷子とは扱わない。

### カメラへ必要になる設計情報

実装に進む場合は、場面ごとに次を持たせる。以下は設計案であり、現行APIに既に存在する機能ではない。

- その場面で見せたい目的地と、今から通る入口。両方が収まる構図を判断する。
- キャラクターを置く画面領域と、目印のために空ける領域。接近距離を維持しながら注視点を調整する。
- いつから次の目印を見せ、いつまで前の目印を残すか。位置の境界だけで急に切り替えない。
- 遮蔽時に採る代替の位置・注視先。キャラクター、着地点、歩ける入口の可視性を優先する。
- 逆走時や横道からの再合流時の見え方。境界で振動しない切り替えと、滑らかな復帰。

制御と入力の基準を先に確認し、注視先を変えた結果として意図しない方向へ走る状態を作らない。ジャンプ中に見せ場のためだけに着地点を隠すことも避ける。

## 制作順と、軽さを維持する方法

1. 各技法の「期待する読み」を一文で書く。例：「さっき見えた塔を起点に、次の通りが続くと分かる」。
2. 入口・判断前・判断後の3構図と経路図を先に作る。目印、小物、敵を増やす前に地形とカメラを動かす。
3. 灰色の建物と大きな輪郭で歩いて確認する。次の場所と通れる入口が結びつかなければ美術を足さず配置を直す。
4. 技法の主役となる素材・動きだけを追加する。同じCC0素材群とタイトルの朝の色調へ揃える。
5. 初見の人に名称を伏せて歩いてもらう。受け取った意味が狙いと違えば、解説で正当化せず作り直す。
6. 表現が成立した区間だけを完成美術へ進め、配布版でカメラ・操作・性能を確認する。

静的な輪郭・明暗・材質とメッシュのまとめを優先し、ライトや動く物を一斉に増やす方針は採らない。動きが必要な擬人法も、判断する場所で少数を反応させる。性能確認は入口だけでなく、角の先・屋上・逆走を含め、同じ条件の変更前後を比較する。これらは予算を守る設計方針であって、未実装の性能保証ではない。

## 比較の設計も変える

全技法で地形とカメラを固定すると、時間や構図が主役の技法を使えなくなる。一方、自由に変えた6ステージの成績差を「修辞だけの差」とも言えない。発表用の作品比較と、効果を調べる比較を分ける。

- **作品としての6例**：目的、操作、世界観、近い視点、所要距離の目安を揃え、各技法に合う地形とカメラを作る。各作品全体の分かりやすさを観察する。
- **個別の効果の比較**：同じ街区内で、狙った連鎖を切る版、カメラの受け渡しだけを外す版などを用意する。一度に変える対象を絞る。単に物を消すと情報量まで変わるため、その差も記録する。
- **学習への配慮**：同じ道を繰り返せば覚える。左右反転だけで解決したことにせず、初見か再訪か、体験順、既存のゲーム経験を分けて記録する。

観察するのは到着時間だけではない。最初の進路、判断地点での停滞、目的地をどこだと思ったか、選んだ理由、寄り道からの再定位、誘導の押しつけ感を残す。短時間の到着が、探索の楽しさや広さの感じを失わせていないかも確認する。

移動中に理由を言わせると体験が変わるため、まず自由に遊んでもらい、その後に録画や画像で尋ねる。視線計測がなければ「見た秒数」は計測したとしない。画面に入っていた時間は可視時間として別に記録する。少人数の試遊は失敗点の発見に使い、一般的な優劣の証明とは呼ばない。

### 次の試作を完成扱いにする条件

初見の人が技法名の説明を受けずに、目的地の見当をつけ、見える入口を使って進み、横道からも位置関係を取り戻せること。加えて、狙った手がかりと本人の説明が対応していること。自動クリア、静止画の見栄え、60fpsだけではこの条件の代わりにならない。

発表では「小説等の修辞から、繰り返し・段階化・意味の置き換え・場面間の引き継ぎを抽出し、空間・カメラ・操作へ翻案した」と説明する。実際に試遊で確かめた結果と、まだ設計上の仮説である部分を区別する。

# ことばで道をつくる：定番2・珍しい2・激レア2（配布14の記録）

## 現在の6技法

依頼に合わせて、6枠をすべて技法のコースへ変更した。「定番／珍しい／激レア」は発表の入り口を作るための編集上の目安で、知名度を調査した分類ではない。日本語で紹介する4技法と、ギリシャ語由来の外国語名で紹介する2技法を選んだ。外国語名の技法も、日本語の文章へ応用できる。

| 枠 | 技法 | 元の考え方 | 現在のステージで行う操作 |
|---|---|---|---|
| 定番1 | 擬人法 | 人間以外のものに人の性質・行為を与える | 鉢植えに目と枝の腕を付け、出口側へ手招きさせる |
| 定番2 | 反復法 | 同じ語句や表現を繰り返す | 同じ大きさ・同じ色の庇を、曲がり角から通りの先まで繰り返す |
| 珍しい1 | 換喩（かんゆ） | 密接に関係するもの・属性で対象を表す | カップの図柄から、先にあるカフェを連想させる |
| 珍しい2 | 漸層法（ぜんそうほう） | 強さ・重要度を段階的に増す | 植栽を小→中→大の順に強め、出口側へ注意を移す |
| 激レア1 | Anadiplosis（アナディプロシス） | 前の句の末尾を、次の句の冒頭で繰り返す | 「庇→カップ／カップ→植栽／植栽→庇」と、目印を次のまとまりへ引き継ぐ |
| 激レア2 | Anapodoton（アナポドトン） | 従属節から予想される主節を提示しない | 「門→カップ」を2回示した後、3つ目の門では期待された看板を空け、先の空間を調べたくさせる |

単なる反復とAnadiplosisは区別する。反復は同じ目印が続く「A・A・A」。Anadiplosisは、目印の組を「A→B／B→C／C→A」と受け渡す。Anapodotonは単に物を減らすのではなく、前の例から期待される帰結を作り、その帰結を省く案として設計した。

元の定義を参照した資料：Brigham Young University / Gideon O. Burton, *Silva Rhetoricae*。

- [Personification](https://rhetoric.byu.edu/Figures/P/personification.htm)
- [Figures of Repetition](https://rhetoric.byu.edu/Figures/Groupings/of%20Repetition.htm)（一般的な反復。特定のラテン語名repetitioと同一視しない）
- [Metonymy](https://rhetoric.byu.edu/Figures/M/metonymy.htm)
- [Climax](https://rhetoric.byu.edu/Figures/C/climax.htm)（ここでは重要度・強さを増す広義の漸層として使用）
- [Anadiplosis](https://rhetoric.byu.edu/Figures/A/anadiplosis.htm)
- [Anapodoton](https://rhetoric.byu.edu/Figures/A/anapodoton.htm)

いずれも言語の定義をそのまま3Dに実装したという意味ではなく、注意や期待に働きかける操作を空間へ翻案した仮説である。擬人法は動く手がかりも含むため、他条件との差を「修辞の種類だけによる効果」とは断定しない。

## 制作の狙いと今回の範囲

行き先を矢印や文章で指定せず、プレイヤーが景観から「こちらへ行ってみよう」と考えられる短い街区を比較する。既存の街とカメラを土台に、小説などの修辞技法を新しい道案内の設計へ翻案した。技法名を既存の配置へ付けるだけでなく、以下の対応から比較コースを新しく作った。

修辞は言語の技法であり、植木・看板・庇が文法そのものを持つわけではない。ここでは、関連づけ、打ち切り、構造の転換、段階的な強調という操作を、プレイヤーが見る空間の順序へ置き換える。選んだ技法は小説だけの専用技法ではなく、詩や演説などにも用いられる。効果の人間による検証はこれから行う。

## 比較できる6コース

目的は全コース共通の「奥のカフェを探す」。歩行面、建物の衝突、近いカメラ、操作、朝の光、出発位置、到着位置を揃え、追加の手がかりを変える。敵・収集物・経路を指示するHUDは置かない。左右どちらを選んでも奥で合流して到着でき、最初の選択を正誤とは呼ばない。

| 番号 | 技法・条件 | 原義 | 空間への翻案 | 今回の実装と観察したいこと |
|---|---|---|---|---|
| 1 | 対照 | 比較のための基準 | 追加の修辞的手がかりを入れない | 建物と通れる空間からカフェを探す。全く無誘導という意味ではない |
| 2 | 換喩 / metonymy | 密接に関係する属性や関連物で対象を表す | カップで、その先のカフェを指し示す | 分岐近くの壁へ共通のカップ図柄を追加。図柄から行き先を連想するか |
| 3 | 黙説法 / aposiopesis | 発話を途中で打ち切る | 続くと思った庇の並びを、分岐前で打ち切る | 前面の庇が途中で終わる。その先を補って周囲の通りを調べたくなるか |
| 4 | 破格法 / anacoluthon | 始めた文の構造が予想と違う構造へ移る | 同じ向きの庇の文法を、角で横向きの並びへ切り替える | 前面の反復が側面の庇へ移る。並びの変化に気づいて角を曲がるか |
| 5 | 漸層法 / climax・gradation | 重要度・強さを段階的に増す配列 | 同じ植栽の目印を小→中→大と強める | 分岐前の3つの植栽を段階的に大きくする。強い側へ視線・移動が向くか |
| 6 | 組み合わせ | 複数の表現操作 | 関連づけ、並び、転換、強弱を重ねる | 単独条件より分かりやすいか、情報が多すぎて押しつけに見えるか |

黙説法の原義には感情による言いさしも含まれるが、この試作は感情をそのまま再現せず、「打ち切りによって続きを意識させる」部分を借りる。破格法は単に一つだけ色を変えることとは区別し、並びの方向・組み方が途中で切り替わる案にした。いずれも原義と空間表現が等価だと実証したものではない。

### 発表で使える短い文の例

以下は説明用に作成したオリジナル例で、特定の小説からの引用ではない。

- 換喩：「彼は、駅前の一杯に逃げ込んだ。」飲み物という関連物で、その場所を想起させる。
- 黙説法：「あの店に戻れるなら、私は――。」語られない続きへ注意を向ける。
- 破格法：「あの店へ行くつもりだった私は――道は、右へ折れていた。」始めた構造を完結させず別の構造へ移る。
- 漸層法：「小さな灯りが、いくつもの灯りが、街ぜんたいが、彼を迎えた。」表現の範囲と強さを増す。

## 遊び方と発表での切り替え

タイトル右下の「修辞の街を選ぶ」から比較一覧へ入る。元のSTARTは従来の街区へ入る。空・タイトルの街・メニューの配置は維持し、比較画面への小さな入口を追加した。F6はコース中の一覧へのショートカットで、タイトルのメニュー中には使わない。

| 操作 | 動作 |
|---|---|
| 一覧のボタン / 数字1〜6 | 各コースへ入る |
| WASD / Space | 移動 / ジャンプ |
| R | 同じコース・配置でやり直す |
| Tab・Esc / F6 | コースから一覧へ戻る |
| M | 配置A/Bを反転。コース中は反転した配置で最初から始める |
| B（一覧） | 技法名を隠す比較モードと、名前を示す発表モードを切り替える |
| Esc（一覧） | タイトルへ戻る |

各条件にはA/Bの2配置がある。Bは床・建物・目印・目的地を左右反転する。カメラの向きは全て奥へ向け、角度で特定の条件だけを優遇しない。反転は「いつも右へ進む」と覚えてしまう偏りを減らす補助であり、学習効果を完全に消すものではない。

到着すると短く停止して一覧へ戻る。プレイ中は説明文字を表示しない。結果と技法の説明は一覧だけに表示する。

## 記録と比較方法

最初の移動入力から計時する。到着、やり直し、反転、一覧への退出をCSVに記録する。終了時の中断も、移動を開始していれば記録する。未開始の閲覧は試行に数えない。メニューの表示時間を到着時間へ含めない。CSVは配布フォルダー内の `generated/guidance/trials.csv`。氏名などは収集しない。実装テストの出力先は環境変数 `WP1_GUIDANCE_RESULTS` で別の検証用ファイルへ分ける。

| 項目 | 意味と注意 |
|---|---|
| case_id / layout / blind / status | 条件0〜5、配置A/B、技法名を隠したか、到着または中断の理由 |
| seconds / distance_m | 最初の操作からの秒数と水平移動距離。到着と中断は分けて集計する |
| first_branch | 最初に進んだ分岐。-1は左、+1は右、0は未選択。最短側はAで右、Bで左 |
| decision_seconds | z=10の接近域へ入ってから最初の分岐へ進むまで。実際の思考時間や視線計測ではない |
| backtracks | 一度分岐へ入ってから手前の広場へ戻った回数。探索を失敗とは決めつけない |
| stationary_seconds | 移動開始後、水平位置がほぼ変わらなかった時間。観察・休止・壁への接触を区別しない |

自動記録だけでは「目印を見た」「理解した」「自然だった」は判定できない。終了直後に「何を手がかりにしたか」「行き先はどこだと思ったか」「押しつけがましく感じたか」を聞き、観察票へ残す。見た目の好みと進路の理解も分ける。

初見での効果を比べるなら、参加者ごとに最初に遊ぶ条件を分ける。繰り返し比較する場合も、1→6だけに固定せず、例えば123456、234561、345612、456123、561234、612345のように順序をずらし、A/Bも割り振る。同じ配置を知った後の結果は初見データと混ぜない。少人数の展示では有効性の一般的な証明より、設計意図・気づき・改善点の報告に使う。

## 発表の構成案（約3〜4分）

1. 問題：行き先を示すだけなら矢印で済むが、自由に歩ける感じと発見を残したい。
2. 発想：読者の注意や期待を動かす修辞の操作を、街を歩く順序へ翻案した。
3. 比較：まず対照、次に換喩・黙説法・破格法・漸層法を、同じ分岐前の画像で見せる。原義→空間での操作→予想する行動を一つずつ説明する。
4. 実演：代表の一条件と組み合わせ版を遊び、一覧でA/Bを切り替える。比較モードでは技法名を隠せることを示す。
5. 評価：実際に観察した結果だけを示し、どの手がかりに気づいたかを説明する。未実施なら仮説と今後の評価方法までを述べる。
6. 考察：暗示を弱くすると迷いやすく、重ねすぎると露骨になる。自由さと分かりやすさの調整として、次にどの配置を変えるかを述べる。

説明例：「既存の街区を基盤に、小説などで使われる修辞技法を、道を見つける体験へ翻案しました。例えば換喩では、行き先の名前を表示する代わりに、カップという関連物を置いて、その先のカフェを連想させています。」

## 制作・検証の記録

`scripts/AuthorGuidanceLab.py` が共通の街区を2配置、追加の目印を条件別に静的統合し、6条件×2配置の12シーンと一覧を生成する。QuaterniusとKenneyの既存CC0素材、カップの図柄、朝の照明、既存プレイヤーを再利用する。新しい動的ライトや常駐の説明HUDは追加しない。共通部分は各配置9メッシュ、実行時40〜45オブジェクトで、全12シーンを同時ロードする方式ではない。

この資料は設計と実装の記録で、参加者の実験結果ではない。自動移動やスクリーンショットの確認は到達可能性・表示の検証に使い、人が迷わないことの証明には使わない。

### 実装後の確認（2026年10月15日・配布13）

- 全12配置で、物理移動による分岐の通過、カフェへの到着、CSV記録、一覧への復帰を確認。対照コースでは反対側の道からの到着も確認した。
- 技法名を隠す切り替え、配置A/B、数字キーによるコース選択を確認。タイトルのボタン→一覧→選択コースは、Appと共通のGamePlaybackを使って確認した。
- 一覧と各条件の分岐前をGPUで描画し、看板の手前・裏側の重なりとUVの向きを修正した。最終の画像は `generated/guidance/comparison.png`、一覧は `guidance--1.png`。
- Pythonの新規検証5件と従来の街区検証10件が成功。Releaseのネイティブ検証、ゲームDLLの再コンパイル、配布物の起動・素材・シェーダー検証も成功した。
- 元のタイトルへ追加した2オブジェクトを除くと、既存の全オブジェクト・設定・アセット参照・STARTは変更前と一致する。共通Engine・SceneRuntime・エディターは変更していない。
