# ことばで道をつくる：修辞技法を空間の道案内へ翻案する

## 制作の狙いと今回の範囲

行き先を矢印や文章で指定せず、プレイヤーが景観から「こちらへ行ってみよう」と考えられる短い街区を比較する。既存の街とカメラを土台に、小説などの修辞技法を新しい道案内の設計へ翻案した。技法名を既存の配置へ付けるだけでなく、以下の対応から比較コースを新しく作った。

修辞は言語の技法であり、植木・看板・庇が文法そのものを持つわけではない。ここでは、関連づけ、打ち切り、構造の転換、段階的な強調という操作を、プレイヤーが見る空間の順序へ置き換える。選んだ技法は小説だけの専用技法ではなく、詩や演説などにも用いられる。効果の人間による検証はこれから行う。

## 比較できる6コース

目的は全コース共通の「奥のカフェを探す」。歩行面、建物の衝突、近いカメラ、操作、朝の光、出発位置、到着位置を揃え、追加の手がかりを変える。敵・収集物・経路を指示するHUDは置かない。左右どちらを選んでも奥で合流して到着でき、最初の選択を正誤とは呼ばない。

| 番号 | 技法・条件 | 原義 | 空間への翻案 | 今回の実装と観察したいこと |
|---|---|---|---|---|
| 1 | 対照 | 比較のための基準 | 追加の修辞的手がかりを入れない | 建物と通れる空間からカフェを探す。全く無誘導という意味ではない |
| 2 | 換喩 / metonymy | 密接に関係する属性や関連物で対象を表す | カップで、その先のカフェを指し示す | 分岐近くの壁へ共通のカップ図柄を追加。図柄から行き先を連想するか |
| 3 | 黙説法 / aposiopesis | 発話を途中で打ち切る | 続くと思った庇の並びを、分岐前で打ち切る | 前面の庇が途中で終わる。その先を補って周囲の通りを調べたくなるか |
| 4 | 破格法 / anacoluthon | 始めた文の構造が予想と違う構造へ移る | 同じ向きの庇の文法を、角で横向きの並びへ切り替える | 前面の反復が側面の庇へ移る。並びの変化に気づいて角を曲がるか |
| 5 | 漸層法 / climax・gradation | 重要度・強さを段階的に増す配列 | 同じ植栽の目印を小→中→大と強める | 分岐前の3つの植栽を段階的に大きくする。強い側へ視線・移動が向くか |
| 6 | 組み合わせ | 複数の表現操作 | 関連づけ、並び、転換、強弱を重ねる | 単独条件より分かりやすいか、情報が多すぎて押しつけに見えるか |

黙説法の原義には感情による言いさしも含まれるが、この試作は感情をそのまま再現せず、「打ち切りによって続きを意識させる」部分を借りる。破格法は単に一つだけ色を変えることとは区別し、並びの方向・組み方が途中で切り替わる案にした。いずれも原義と空間表現が等価だと実証したものではない。

### 発表で使える短い文の例

以下は説明用に作成したオリジナル例で、特定の小説からの引用ではない。

- 換喩：「彼は、駅前の一杯に逃げ込んだ。」飲み物という関連物で、その場所を想起させる。
- 黙説法：「あの店に戻れるなら、私は――。」語られない続きへ注意を向ける。
- 破格法：「あの店へ行くつもりだった私は――道は、右へ折れていた。」始めた構造を完結させず別の構造へ移る。
- 漸層法：「小さな灯りが、いくつもの灯りが、街ぜんたいが、彼を迎えた。」表現の範囲と強さを増す。

## 遊び方と発表での切り替え

タイトル右下の「修辞の街を選ぶ」から比較一覧へ入る。元のSTARTは従来の街区へ入る。空・タイトルの街・メニューの配置は維持し、比較画面への小さな入口を追加した。F6はコース中の一覧へのショートカットで、タイトルのメニュー中には使わない。

| 操作 | 動作 |
|---|---|
| 一覧のボタン / 数字1〜6 | 各コースへ入る |
| WASD / Space | 移動 / ジャンプ |
| R | 同じコース・配置でやり直す |
| Tab・Esc / F6 | コースから一覧へ戻る |
| M | 配置A/Bを反転。コース中は反転した配置で最初から始める |
| B（一覧） | 技法名を隠す比較モードと、名前を示す発表モードを切り替える |
| Esc（一覧） | タイトルへ戻る |

各条件にはA/Bの2配置がある。Bは床・建物・目印・目的地を左右反転する。カメラの向きは全て奥へ向け、角度で特定の条件だけを優遇しない。反転は「いつも右へ進む」と覚えてしまう偏りを減らす補助であり、学習効果を完全に消すものではない。

到着すると短く停止して一覧へ戻る。プレイ中は説明文字を表示しない。結果と技法の説明は一覧だけに表示する。

## 記録と比較方法

最初の移動入力から計時する。到着、やり直し、反転、一覧への退出をCSVに記録する。終了時の中断も、移動を開始していれば記録する。未開始の閲覧は試行に数えない。メニューの表示時間を到着時間へ含めない。CSVは配布フォルダー内の `generated/guidance/trials.csv`。氏名などは収集しない。実装テストの出力先は環境変数 `WP1_GUIDANCE_RESULTS` で別の検証用ファイルへ分ける。

| 項目 | 意味と注意 |
|---|---|
| case_id / layout / blind / status | 条件0〜5、配置A/B、技法名を隠したか、到着または中断の理由 |
| seconds / distance_m | 最初の操作からの秒数と水平移動距離。到着と中断は分けて集計する |
| first_branch | 最初に進んだ分岐。-1は左、+1は右、0は未選択。最短側はAで右、Bで左 |
| decision_seconds | z=10の接近域へ入ってから最初の分岐へ進むまで。実際の思考時間や視線計測ではない |
| backtracks | 一度分岐へ入ってから手前の広場へ戻った回数。探索を失敗とは決めつけない |
| stationary_seconds | 移動開始後、水平位置がほぼ変わらなかった時間。観察・休止・壁への接触を区別しない |

自動記録だけでは「目印を見た」「理解した」「自然だった」は判定できない。終了直後に「何を手がかりにしたか」「行き先はどこだと思ったか」「押しつけがましく感じたか」を聞き、観察票へ残す。見た目の好みと進路の理解も分ける。

初見での効果を比べるなら、参加者ごとに最初に遊ぶ条件を分ける。繰り返し比較する場合も、1→6だけに固定せず、例えば123456、234561、345612、456123、561234、612345のように順序をずらし、A/Bも割り振る。同じ配置を知った後の結果は初見データと混ぜない。少人数の展示では有効性の一般的な証明より、設計意図・気づき・改善点の報告に使う。

## 発表の構成案（約3〜4分）

1. 問題：行き先を示すだけなら矢印で済むが、自由に歩ける感じと発見を残したい。
2. 発想：読者の注意や期待を動かす修辞の操作を、街を歩く順序へ翻案した。
3. 比較：まず対照、次に換喩・黙説法・破格法・漸層法を、同じ分岐前の画像で見せる。原義→空間での操作→予想する行動を一つずつ説明する。
4. 実演：代表の一条件と組み合わせ版を遊び、一覧でA/Bを切り替える。比較モードでは技法名を隠せることを示す。
5. 評価：実際に観察した結果だけを示し、どの手がかりに気づいたかを説明する。未実施なら仮説と今後の評価方法までを述べる。
6. 考察：暗示を弱くすると迷いやすく、重ねすぎると露骨になる。自由さと分かりやすさの調整として、次にどの配置を変えるかを述べる。

説明例：「既存の街区を基盤に、小説などで使われる修辞技法を、道を見つける体験へ翻案しました。例えば換喩では、行き先の名前を表示する代わりに、カップという関連物を置いて、その先のカフェを連想させています。」

## 制作・検証の記録

`scripts/AuthorGuidanceLab.py` が共通の街区を2配置、追加の目印を条件別に静的統合し、6条件×2配置の12シーンと一覧を生成する。QuaterniusとKenneyの既存CC0素材、カップの図柄、朝の照明、既存プレイヤーを再利用する。新しい動的ライトや常駐の説明HUDは追加しない。共通部分は各配置9メッシュ、実行時40〜45オブジェクトで、全12シーンを同時ロードする方式ではない。

この資料は設計と実装の記録で、参加者の実験結果ではない。自動移動やスクリーンショットの確認は到達可能性・表示の検証に使い、人が迷わないことの証明には使わない。

### 実装後の確認（2026年10月15日・配布13）

- 全12配置で、物理移動による分岐の通過、カフェへの到着、CSV記録、一覧への復帰を確認。対照コースでは反対側の道からの到着も確認した。
- 技法名を隠す切り替え、配置A/B、数字キーによるコース選択を確認。タイトルのボタン→一覧→選択コースは、Appと共通のGamePlaybackを使って確認した。
- 一覧と各条件の分岐前をGPUで描画し、看板の手前・裏側の重なりとUVの向きを修正した。最終の画像は `generated/guidance/comparison.png`、一覧は `guidance--1.png`。
- Pythonの新規検証5件と従来の街区検証10件が成功。Releaseのネイティブ検証、ゲームDLLの再コンパイル、配布物の起動・素材・シェーダー検証も成功した。
- 元のタイトルへ追加した2オブジェクトを除くと、既存の全オブジェクト・設定・アセット参照・STARTは変更前と一致する。共通Engine・SceneRuntime・エディターは変更していない。

720pの診断用コピーで、各360フレームから先頭10を除く350サンプルを計測した。固定の診断入力による分岐前の短い動作であり、全コースの通し計測ではない。前半は物理検証と重なったため、他プロセスを排除した厳密なベンチマークとしては扱わない。

| 条件 | フレーム平均 | p95 | CPU更新平均 | GPU全体平均 |
|---|---:|---:|---:|---:|
| 対照 A | 16.669ms | 17.440ms | 0.669ms | 0.476ms |
| 破格法 A | 16.666ms | 17.328ms | 0.709ms | 0.487ms |
| 組み合わせ A | 16.665ms | 17.311ms | 0.710ms | 0.499ms |
| 組み合わせ B | 16.668ms | 17.364ms | 0.673ms | 0.497ms |

この短時間計測では平均約60fps相当。単発の最長フレームは42.136msで、常時60fpsや他のPCでの性能を保証する値ではない。集計とCSVは `generated/guidance/performance.json` と `profile-*.csv`。自動攻略・描画の最終ログは `generated/guidance-physics-final.log` と `guidance-render-final.log`。

配布13は保存済みAssetsを梱包し、ゲームDLLとシェーダーを再生成した。起動シーンがnullになる既存の配布メタデータは出力側で補正し、描画確認後の最終データも反映してハッシュを更新した。配布処理本体は変更していない。
