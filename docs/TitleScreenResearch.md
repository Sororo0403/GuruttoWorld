## 1. 調査結果と推奨する方向

目標は「かわいい主人公で、未知の世界へ冒険に出たくなる、かっこいいタイトル画面」。作品を象徴するモチーフを先に決め、色・文字・構図・動き・音に展開する。

現段階の推奨案は、背景・主人公・ロゴを別々の画像として重ね、移動量の差で奥行きを作る構成。WP1 の既存スプライト機能を利用しやすい。これは調査からの提案であり、ユーザーが採用を決めた仕様ではない。

| 参考作品 | 取り入れる考え方 | WP1 での応用案 |
|---|---|---|
| ペルソナ5 / P5R | 選択と画面構図を結び付ける | 項目の強調と同時に、主人公や背景の位置を少し変える |
| ペルソナ3 リロード | 作品のテーマを動きまで一貫させる | 「発見」を軸に、開く・飛び出す・広がる動きで統一 |
| 星のカービィ ディスカバリー | 新世界への期待と、選びやすいメニューを両立 | 明るい冒険風景を見せ、操作部分は整理する |
| スプラトゥーン3 | 世界の文化を背景とグラフィックで伝える | 自作世界の看板や模様を UI と共有する |
| Hi-Fi RUSH | 音楽・アニメーション・画面表現を結び付ける | 決定音とロゴや主人公の動きの節目を合わせる |

ピンク、廃墟の街、星、2 秒の登場演出は、これまでの会話で出した仮案。ペルソナやカービィの実測値・公式仕様ではない。

## 4. 開発者資料から得た根拠

### ペルソナ

P5 の開発者講演では、メインカラーを軸にロゴや書体を決め、線・明暗・構図変更で視線や階層認識を助けると説明されている。3D の動きから 2D の決め絵へつなぐ工程も紹介されている。タイトル画面だけの仕様ではなく、UI 全体の制作原則として参照する。

出典：[ファミ通・CEDEC＋KYUSHU 2017 講演レポート / 2017-11-13](https://www.famitsu.com/news/201711/13145540.html)

P3R では水と主人公の内面を結び付け、浮遊感や反射を表現している。メニュー用の専用モデルを用意し、静止画の美しさだけでなく実際の操作性を検討した。専用モデルの制作規模を WP1 の最初のタイトル画面にそのまま要求する必要はない。

出典：[ファミ通・P3R UI インタビュー / 2023-11-29](https://www.famitsu.com/news/202311/29325647.html)

### カービィ：明るい冒険世界と導入の役割

開発者は、廃墟が怖く見えないよう青空や色鮮やかな植物を取り入れ、かつての楽しさが感じられる世界を目指したと説明する。架空言語の歌は、異世界に到着したカービィとプレイヤーに、未知の場所を訪れる感覚を共有させる狙いがある。これは導入・世界観の説明であり、タイトルのボタン配置に関する発言ではない。

出典：[任天堂・Ask the Developer Vol. 4 / 2022-03-24、Chapter 3](https://www.nintendo.com/en-za/News/2022/March/Ask-the-Developer-Vol-4-Kirby-and-the-Forgotten-Land-2187039.html)

応用案：背景を採用する場合は、荒廃の細部より、空の抜け・植物・遠くの目的地を重視する。音楽にも未知の世界へ進む期待を持たせる。廃墟そのものはユーザーの必須条件ではない。

### スプラトゥーン：装飾を世界の文化と結び付ける

開発者は、3 の混沌というテーマ、時代の違う建物が密集する街、ストリート文化と作品ごとの価値観の変化を説明している。単に色数を増やすのではなく、世界の文化とグラフィックの関係を参考にする。

出典：[任天堂・Ask the Developer Vol. 7, Chapter 1 / 2022年](https://www.nintendo.com/au/news-and-articles/ask-the-developer-vol-7-splatoon-3-chapter-1/)

応用案：世界に登場する看板、地図、マーク、乗り物などから UI の形を選ぶ。主人公や舞台が未決定の段階では、インクや怪盗のモチーフをそのまま採用しない。

### Hi-Fi RUSH：音と動きの共通ルール

開発者は、音楽に同期する世界と UI を試作し、色鮮やかさ・鋭さ・明快さをアートの軸にしたと説明している。同期には音楽の拍情報を各要素へ伝える仕組みがあり、単に同時に再生するだけではない。

出典：[Unreal Engine・開発者インタビュー / 2023-03-16](https://www2.unrealengine.com/developer-interviews/hi-fi-rush-was-inspired-by-shaun-of-the-dead-and-futurama)

応用案：最初は決定音と演出の節目を合わせる。厳密な BGM 拍同期を行う場合は、再生位置を基準にする設計を別途用意する。次の拍を待つためにメニュー入力の反応を遅らせない。

補助資料：[IMAGICA GEEQ・開発陣インタビュー後編](https://hr.geeq.co.jp/tocreator/interview/tangogameworks-creators-2/)。UI 担当者は一般的な使いやすさと独自性の両立について述べている。掲載時点の今後の制作姿勢を含むため、Hi-Fi RUSH のタイトル画面専用仕様とは区別する。

## 5. 文字・操作の読みやすさ

### 公開ガイドラインの数値

| 項目 | 参照する基準 | 出典 |
|---|---|---|
| 1080p の文字 | コンソールでは最低 26 px、PC/VR では最低 18 px を推奨 | [Microsoft XAG 101](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/101) |
| 文字拡大 | 最小文字サイズの 200% まで拡大しても情報・機能を失わない | [XAG 101](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/101) |
| 一般的な文字・重要な視覚要素 | 背景に対して 4.5:1 以上のコントラスト | [XAG 102](https://learn.microsoft.com/en-us/gaming/accessibility/xbox-accessibility-guidelines/102) |
| 大きな文字 | 3:1 以上。1080p での大文字の定義はコンソール 52 px、PC/VR 36 px | [XAG 102](https://learn.microsoft.com/en-us/gaming/accessibility/xbox-accessibility-guidelines/102) |
| 選択状態 | 色だけに依存せず、形・アイコンなどを併用 | [XAG 103](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/103) |
| 動く背景 | 文字のある UI の自動アニメーションを停止・無効化できる配慮 | [XAG 117](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/117) |

XAG の数値は参考ガイドラインであり、ペルソナの実測値ではない。文字の寸法はフォントファイルの指定値と同一とは限らず、XAG 101 では body height を基準にする。日本語も実際に描いた字面と潰れを確認する。動く背景は最も読みにくくなる部分・状態でコントラストを確認する。

### WP1 向けの提案値・確認項目

- 1280×720 で設計確認する。主メニューの日本語は字面高さ約 28～36 px、操作案内は約 20～24 px を初期案とする。1080p 相当ではそれぞれ約 42～54 px、30～36 px。これは自作案の出発点であり検証済みの最適値ではない。
- 日本語のメニューはまず横組みで安定させ、斜めの勢いは帯・背景・ロゴで出す。
- 選択中は明るい面、輪郭、印、少しの拡大を組み合わせる。音を消しても選択・決定が分かるようにする。
- 候補書体は Noto Sans JP の太いウェイトと M PLUS Rounded 1c。前者で明快さ、後者で丸みとの相性を比べる。これは美術上の候補で、各書体の読みやすさを実測した結論ではない。
- 「はじめる」「設定」「終了」など実際の日本語、英数字、ボタン記号を並べて確認する。ロゴ用の加工文字と操作説明の文字は目的を分ける。
- 文字を拡大したときのはみ出し、グレースケールでの選択状態、画面の縮小、テレビ相当の視聴距離、連続入力時を確認対象とする。
- 背景を大きく動かす案には、動きを抑える状態も設計する。

書体の参照：[Google Fonts 日本語公式一覧](https://googlefonts.github.io/japanese/)、[Noto Sans JP](https://fonts.google.com/noto/specimen/Noto+Sans+JP)、[M PLUS Rounded 1c](https://fonts.google.com/specimen/M+PLUS+Rounded+1c)。素材化や同梱はまだ行っていない。

## 6. WP1 の現状と実現方法

ソースコードの読み取り結果。ビルド・アプリ起動・性能計測は行っていない。

| 機能 | 現状 | タイトル画面への意味 |
|---|---|---|
| タイトルシーン | 背景色と開発用 ImGui 案内。Enter で Game に遷移 | 配布用のタイトル描画は新規に必要。Release では案内は描かれない |
| 初期解像度 | 1280×720 | 基準座標とリサイズ時の拡縮・余白を決める |
| 2D スプライト | 位置・サイズ・中心回転・色/透明度・UV 切り出し、後描画が手前 | ロゴ、帯、主人公の切り抜き、フェード、画像差し替えに使用可能 |
| テクスチャ | WIC による画像読込と共有管理 | PNG 等の素材を分割して準備できる。任意の SVG を直接描く機能ではない |
| 3D | OBJ を想定した読み込み、静的メッシュ描画、変換、カメラ | 静的な背景や立体物の回転・移動は構成できる |
| キャラクターの骨格アニメーション | 現行 MeshVertex にボーン情報がなく、読込処理にもアニメーション保持を確認できない | P5/P3R のような自在な 3D ポーズ変化は別途機能が必要 |
| パーティクル | 既存 GameScene で描画例あり | ほこりや光の粒の基盤にできる。タイトル用表現の調整は必要 |
| 音声 | XAudio2、読込、再生、ループ、停止、音量変更 | BGM と決定 SE の基盤がある |
| 音楽との同期 | 公開 AudioSystem API に再生位置・拍通知は見当たらない | 厳密な拍同期は追加設計が必要。フレーム時間だけでは音とのずれを保証できない |
| 入力 | Keyboard と XInput Gamepad がある。GameScene が Gamepad を所有 | タイトルでは現在 Enter のみ。ゲームパッド・上下選択などは接続が必要 |
| 日本語の製品用文字描画 | 独自ソースでフォントレンダラーを確認できず、表示例は開発用 ImGui | 固定ラベル画像か、文字描画機能を用意する |
| マスク・遷移 | Sprite.hlsl は画像サンプルと色の乗算。シーン管理は生成・交換型 | 単純な帯の移動は構成可能。任意形状のくり抜きやクロスフェード管理は追加作業 |
| セーブ・設定画面 | ゲーム用のセーブ/ロードや設定メニュー実装は調査範囲で見当たらない | 「つづきから」を動く機能として前提にしない |
| 完成素材 | Checker.png、Sample.wav、Cube/Pyramid モデル等のサンプル | 主人公、背景、ロゴ、UI、音楽の素材は新しく用意する |

### 作り方の比較

| 案 | 素材と追加作業 | 相対的な作業量 | 評価 |
|---|---|---|---|
| 背景・主人公・UI の多層画像 | 背景数層、主人公の静止ポーズ差分、ロゴ、ラベル、状態管理 | 小～中 | 最初の候補。構図と切り替えの完成度に集中しやすい |

作業量は機能の差に基づく相対評価で、日数見積もりではない。絵・モデルの完成度と必要差分数で大きく変わる。

### 最初の案に必要な素材

- 遠景、街や地形の中景、手前の葉や看板など。画面移動用に外側の描き足しを含む。
- 主人公の待機ポーズと開始ポーズ。必要なら表情差分。
- ゲーム名のロゴ。名称が未確定なら仮の文字で配置を評価する。
- メニューの通常/選択状態、操作案内、キーボードとゲームパッドの記号。
- 画面切り替え用の形状。初期案は矩形や画像の移動で成立させる。
- ループ BGM、選択、決定、戻るの SE。長さや曲調は画面案と一緒に決める。

固定ラベル画像は最初の短いメニューには使いやすいが、長文の設定画面・多言語・可変文字・拡大には文字描画基盤の方が扱いやすい。

### コード構成から分かる注意点

SceneManager は切り替え時に GPU の完了を待ち、次のシーンを Initialize してから交換する。リソース読み込みを含めた遷移時間は未計測なので、滑らかなクロスフェードや待ち時間ゼロを現状の保証として書かない。

TitleScene は現在アセットのルートパスを受け取っていない。素材を使う際は GameScene と同様に受け取る等の配線が必要。音声をシーンごとに持つ案ではシーン切り替え時の BGM 継続も設計対象になる。

## 7. 実装前に作るべき設計資料

次の作業は、調査の追加より、今回のゲーム用に選択肢を絞ること。

1. 主人公と舞台を踏まえて、テーマを一文にする。「未知の世界へ飛び出す」は仮置き。
2. 同じ内容で構図を 3 案比較する：主人公を大きく置く案／世界を広く見せる案／グラフィックを強く押し出す案。
3. 入力待ち、メニュー、決定直後、遷移の 4 状態を絵コンテにする。
4. 色・日本語書体・音の方向を各案に添え、縮小してもロゴと選択項目が分かるか確認する。
5. 選んだ案について素材一覧と画面状態を確定し、その後に実装する。

最初の機能案は「はじめる／設定／終了」。セーブができる段階で「つづきから」を追加する。設定項目は BGM/SE 音量や動きの抑制など、必要な機能に合わせて確定する。現段階でこれらを実装したという意味ではない。

## 8. 残る不確定事項

- 公開映像では入力の瞬間が記録されていないため、反応速度、スキップ可能時刻、長押し・連打挙動は断定できない。
- 初回起動、既存セーブ、クリア後、DLC、プラットフォームによる全変種は網羅していない。
- P5R は発売前の参考映像。製品版の完全なメニュー構成の根拠には使わない。
- 音の評価は開発者資料に基づく。今回のブラウザーでの映像観察は消音で行った。
- WP1 の機能評価はコードの読み取り。実際の描画品質、起動時間、フレーム時間、音の遅延は、後の試作で測定する。
- 主人公、ゲーム名、世界の設定はまだ確定していない。色やモチーフの最終決定はそれらに合わせる。

本調査ではゲームのソース・ビルド設定・既存アセットを変更していない。
