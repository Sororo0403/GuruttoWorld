# 路地から屋上へ進む一本の街区（StreetJourney）

## カメラ演出の設計と発表用の説明

2026-10-15。以下は制作資料だけに置く説明。技法名・分類・解説・比較用のUIや入力はゲームへ入れない。以前の六つの比較ステージも復活させない。

言語の修辞を、見せる順番と視点の変化へ翻案した。言葉そのものを表示したり、文学上の技法とカメラ動作が同一であると主張したりするものではない。発表では「小説などで用いられる修辞技法を参考に、視点の対比・繰り返し・段階的な展開を設計した」と説明できる。効果が実証されたという説明にはしない。

| 参考にした考え方 | 実際の演出 |
|---|---|
| 対比 | 入口は低く近い画角、カフェへ出ると横から高めの画角へ変化させる。狭い路地の圧迫感と、開けた場所の見通しの差を作る |
| 反復 | 最初の水路ジャンプと屋上のジャンプに、右側から回り込み、着地側を含めて見渡す似た構図を使う。二度目に同じ見せ方を再提示する |
| 漸層 | 階段の途中では低めに寄り、屋上へ出るにつれて側方・高さ・距離・画角を広げる。上り切った場面で街の広がりを見せ、最後は出口へ寄る |

制御は位置・注視点・画角を分けて滑らかに動かす。左右の回り込み、クレーン、寄り引きを行い、歯車を操作した直後には階段方向を短く予告する。画角は入口53度から屋上64度まで変化し、出口では52度へ寄る。カメラの傾きによる画面の回転や常時の振動は加えない。壁との遮蔽検査、落下復帰時の追従リセット、向きの速度制限を残す。入力方向を反転させるような後方への周回はしない。

『ディスカバリー』の開発者が説明する、遊びに合わせてレベルデザイナーが各場所のカメラを決める方針を参考にした。[任天堂・カメラと遊びの融合](https://www.nintendo.com/jp/interview/arzga/02.html)。修辞の参考定義は[Silva Rhetoricae・antithesis](https://rhetoric.byu.edu/Figures/A/antithesis.htm)、[反復に関する分類](https://rhetoric.byu.edu/Figures/A/anaphora.htm)、[climaxの広義の段階的配列](https://rhetoric.byu.edu/Figures/C/climax.htm)。anaphoraは特に語句の冒頭反復を指すため、今回の演出名をanaphoraとは呼ばず、反復という考え方だけを参考にする。


2026-10-15更新。通常ステージ用の `StreetJourney.cpp`、`StreetPlayer`、`StreetCamera`、`StreetGear` として独立させた。Escでタイトルへ戻る。

広場を歩き回る方式をやめ、STARTから一本の連続した街区へ入る構成に変更した。本線と短い寄り道を備える通常ステージとして制作する。

| 場面 | 遊びと空間 |
|---|---|
| 入口の路地 | 両側の実寸感のある建物の間を進み、カフェ前の開けた場所を発見する |
| カフェ前 | 幅2mの排水路を跳び、少し高いテラスへ渡る。敵との間合いを取りながら進む |
| 店脇の分岐 | キオスク両側に入口を設ける。短いサービス路地で収集物を見つけ、先の本線へ合流する |
| 裏庭 | 植え込みを回り、敵と対処し、歯車をJで操作して屋上階段の扉を開く |
| 屋上 | 十二段の階段で上り、離れた隣の屋上へ跳び移る。下には失敗を受ける庇を設ける |
| 出口 | 次の街並みを望む門へ到着する。到着後も歩ける |

70×76mの共通床は使わず、路地・カフェのテラス・店脇・裏庭・屋上ごとに実際の床と衝突面を作った。建物は通路の境界や屋上の支持体として使う。CC0の建築部品と家具、既存の空と光、主人公と操作を引き継ぐ。プレイ中の説明文字は表示しない。カメラは場面ごとに横位置・高さ・距離を滑らかに変え、カフェの着地点、分岐の入口、高所の足場を見せる。チェックポイント復帰のような大きな位置変更ではカメラも復帰先へ合わせる。

制作元は `scripts/AuthorStreetJourney.py`。同スクリプトのみで新街区とタイトルのSTART接続を生成する。`Assets/Models/StreetJourney/Route.json` に本線・ジャンプ・短い寄り道を保存する。

確認：データと既存制作物の検査14件が成功。ゲーム用のシーン・タイトル・入力設定・カメラ処理へ技法名や解説が混入していないことも検査した。実物理による2948フレームの試行で、最初のジャンプ、寄り道の収集と合流、歯車による開放、落下復帰、屋上階段、屋上間ジャンプ、庇からの復帰、到着、Escでタイトルへ戻る動作が成功。カメラ距離、壁との遮蔽、通常移動中の旋回速度、画角の上下限を各フレームで検査した。観測した左右の向きの幅は1.13428rad（約65度）、画角は53〜63.848度だった。目標の画角へは時間をかけて追従するため、短い到着待ち時間で最終値52度まで収束することは求めていない。

タイトルSTARTからの連続描画2047フレームで出口へ到着し、137枚を `generated/street-camera/walkthrough.gif` に保存。代表画像は同フォルダーの `review.png`。配布24は832ファイルのハッシュ不一致0、制作データとの不一致0、`--validate-package` 成功。720p・入口／カフェ／分岐／屋上の4条件各360フレーム（最初の10を除外）で、平均フレーム間隔16.600〜16.673ms、CPU更新1.066〜1.087ms、GPU全体1.375〜4.086ms。単発の最長41.148msは残る。短時間の診断であり、全場面や他のPCを保証しない。集計は `generated/street-camera/performance.json`。

これは経路を知る自動プレイの確認で、初見の人が迷わず進めることや面白さの検証ではない。最短経路の自動描画は約34秒、寄り道と復帰を含む物理試行は約49秒。初見60〜90秒は目標であり、実測済みとは扱わない。

設計の根拠は[ディスカバリーの遊びの密度](https://www.nintendo.com/jp/interview/arzga/index.html)、[場面ごとのカメラ](https://www.nintendo.com/jp/interview/arzga/02.html)、[遊びと舞台の対応](https://www.nintendo.com/jp/interview/arzga/03.html)、[3Dランドの本線と探索](https://www.nintendo.co.jp/3ds/interview/arej/vol1/index2.html)、[ブロックアウトでの反復検証](https://book.leveldesignbook.com/process/blockout)。
