# 路地から屋上へ進む一本の街区（StreetJourney）

## カメラの調査と調整

2026-10-15。前回は場面ごとに左右を往復させ、画角の変化と操作後のせり上がりを重ねたため、カメラ自体が目立ちすぎた。通常移動を見やすく保つ構成へ変更した。

公開資料で確認できる『ディスカバリー』の方針は、場所の遊びに合う見下ろし・横方向の視点をデザイナーが設定し、探索中も進行方向を保ち、次に扱う敵や仕掛けを分かりやすく映すこと。[任天堂・開発者に訊きました第2章](https://www.nintendo.com/jp/interview/arzga/02.html)。公開説明には具体的な角度・補間速度・ズームの数値は示されていないため、以下の数値や制御は本作向けの独自調整である。GDC講演は[公式の講演概要](https://gdcvault.com/play/1029356/The-Many-Dimensions-of)を確認したもので、動画全体を解析したとは扱わない。

| 調整 | 実装 |
|---|---|
| 各場所で方向を安定させる | 入口・カフェ以降・屋上の3構成を基本に、裏庭の入口では構図全体を少し横移動する。同じ側から映し、左右の往復を廃止する |
| つなぎでだけ緩やかに変える | 路地からカフェ、裏庭の入口、階段から屋上へ入る間に横位置と高さを少し変える。ジャンプ中や戦闘中に別の画角へ切り替えない |
| 距離感を保つ | 画角は58度固定。ズームの繰り返しと出口での急な寄りを廃止する。追従の遅れを含むカメラ距離も10.6m以内に抑える |
| 操作に視点を引きずらせない | 小さな移動を吸収する追従の余裕を設け、位置と注視点を同じ速さで追従させる。後退で注視点を急に反転させない |
| 操作後に落ち着かせる | 歯車操作後の自動クレーンを廃止。停止中の位置と向きが収束することを検査する |
| 壁と落下に対応する | 壁との遮蔽検査、同じ側での近接補正、復帰時の追従リセットを残す。旋回速度の上限を毎秒約26度に抑える |

## 発表用の説明（ゲーム外のみ）

技法名・分類・解説・比較UIをゲームへ入れない。以前の比較ステージも復活させない。「修辞技法を参考に、見せる順番や空間の差を考えた」と説明できるが、効果を実証したという説明にはしない。

| 参考にした考え方 | 現在の演出との対応 |
|---|---|
| 対比 | 路地の圧迫感とカフェの見通しの差。カメラを大きく振らず、空間の違いを読ませる |
| 反復 | 最初の水路ジャンプと屋上ジャンプを、同じ側・一定の画角で映し、距離感を再利用できるようにする |
| 漸層 | 地形の上昇に沿って、階段から屋上へ少しずつ視点を高くする |

言語の技法からカメラの構成への翻案であり、文学上の技法そのものをゲーム内へ表示するものではない。参考定義：[Silva Rhetoricae・antithesis](https://rhetoric.byu.edu/Figures/A/antithesis.htm)、[反復の一例anaphora](https://rhetoric.byu.edu/Figures/A/anaphora.htm)、[climaxの広義の段階的配列](https://rhetoric.byu.edu/Figures/C/climax.htm)。anaphoraは語句の冒頭反復を指すため、今回の演出をその技法名で呼ばない。

2026-10-15更新。通常ステージ用の `StreetJourney.cpp`、`StreetPlayer`、`StreetCamera`、`StreetGear` として独立させた。Escでタイトルへ戻る。

広場を歩き回る方式をやめ、STARTから一本の連続した街区へ入る構成に変更した。本線と短い寄り道を備える通常ステージとして制作する。

| 場面 | 遊びと空間 |
|---|---|
| 入口の路地 | 両側の実寸感のある建物の間を進み、カフェ前の開けた場所を発見する |
| カフェ前 | 幅2mの排水路を跳び、少し高いテラスへ渡る。敵との間合いを取りながら進む |
| 店脇の分岐 | キオスク両側に入口を設ける。短いサービス路地で収集物を見つけ、先の本線へ合流する |
| 裏庭 | 植え込みを回り、敵と対処し、歯車をJで操作して屋上階段の扉を開く |
| 屋上 | 十二段の階段で上り、離れた隣の屋上へ跳び移る。下には失敗を受ける庇を設ける |
| 出口 | 次の街並みを望む門へ到着する。到着後も歩ける |

70×76mの共通床は使わず、路地・カフェのテラス・店脇・裏庭・屋上ごとに実際の床と衝突面を作った。建物は通路の境界や屋上の支持体として使う。CC0の建築部品と家具、既存の空と光、主人公と操作を引き継ぐ。プレイ中の説明文字は表示しない。カメラは場面ごとに横位置・高さ・距離を滑らかに変え、カフェの着地点、分岐の入口、高所の足場を見せる。チェックポイント復帰のような大きな位置変更ではカメラも復帰先へ合わせる。

制作元は `scripts/AuthorStreetJourney.py`。同スクリプトのみで新街区とタイトルのSTART接続を生成する。`Assets/Models/StreetJourney/Route.json` に本線・ジャンプ・短い寄り道を保存する。

確認：データ・既存制作物の検査14件、実物理3218フレーム、STARTから出口までの連続描画2047フレームが成功。移動中のカメラ距離・壁との遮蔽・旋回速度を検査し、歯車を操作した後に3秒待機し、さらに1.5秒停止して位置と向きが変わらないことを確認した。全経路で観測した左右の向きの幅は0.217208rad（約12.4度）、画角は58度固定。前版の約65度・53〜63.848度の画角変化から抑えた。ジャンプ、寄り道、扉、落下復帰、屋上、庇からの復帰、到着、Escでタイトルへ戻る動作も成功。

動画は `generated/street-calm/walkthrough.gif`、代表画像は `review.png`。配布25は832ファイルのハッシュ不一致0、制作データとの不一致0、`--validate-package` 成功。720p・4条件各360フレーム（最初の10を除外）の短時間診断は、平均フレーム間隔16.635〜16.645ms、CPU更新1.072〜1.182ms、GPU全体2.817〜2.944ms。単発の最長33.545msは残る。他のPCや全場面を保証するものではない。集計は `generated/street-calm/performance.json`。

これは経路を知る自動プレイの確認で、初見の人が迷わず進めることや面白さの検証ではない。最短経路の自動描画は約34秒、停止確認・寄り道・復帰を含む物理試行は約54秒。初見60〜90秒は目標であり、実測済みとは扱わない。

設計の根拠は[ディスカバリーの遊びの密度](https://www.nintendo.com/jp/interview/arzga/index.html)、[場面ごとのカメラ](https://www.nintendo.com/jp/interview/arzga/02.html)、[遊びと舞台の対応](https://www.nintendo.com/jp/interview/arzga/03.html)、[3Dランドの本線と探索](https://www.nintendo.co.jp/3ds/interview/arej/vol1/index2.html)、[ブロックアウトでの反復検証](https://book.leveldesignbook.com/process/blockout)。

## カメラだけを変えた比較配布版

`scripts/BuildStreetCameraComparison.py` で同じReleaseスナップショットから `Good/App.exe` と `Bad/App.exe` を作る。両方とも同じタイトルのSTARTから同じ街区へ入り、比較メニューや解説は表示しない。通常の制作データはGoodのままにする。

- Good：現在の穏やかなカメラ。カフェ・屋上への移動に合わせ、同じ側のまま横位置・高さ・距離を調整する。画角58度。
- Bad：`StreetCamera` の数値設定 `fixedView=1`。入口のカメラ配置を全区間に適用し、角度と通常距離、画角58度を固定する。プレイヤー位置と地面への追従、平滑化、壁へのめり込み防止は残す。場面ごとの構図変更・角の別構図への切り替えはしない。

ここでのBadは「場面に応じた構図設計を外した比較条件」という意味。前の大きな旋回・ズームを再利用するものではない。固定カメラ自体の良し悪しや、初見での誘導効果を実証したという意味でもない。

作成例：`python scripts/BuildStreetCameraComparison.py`。既にReleaseのプレイヤー本体をビルド済みの場合は `--skip-player-build` を付けられる。ゲーム処理のDLLは必ず新規コンパイルする。出力先は `Games/GuruttoWorld/generated/builds/CameraComparison-<run-id>/`。両配布版の起動検証と全ファイルのハッシュ確認を行い、ゲーム内容の差分がステージのカメラ設定一つだけであることを検査する。

物理経路検査は `WP1_JOURNEY_ONLY=1` と `WP1_SUNRISE_CPU_ONLY=1`、固定カメラ条件には追加で `WP1_JOURNEY_FIXED_VIEW=1`。`WP1_JOURNEY_CONTENT` に配布フォルダーを指定すると、その配布シーンを検査する。描画検査はCPU_ONLYを外し、RENDER_ONLYを指定するとタイトルのSTARTから出口までの連続描画を検査する。

比較配布26の確認：両条件それぞれ物理3218フレームとSTARTから出口までの描画2047フレームが成功。Goodの左右角度の幅は0.217208rad、Badは0radで上下角度も固定、両方とも画角58度。データ検査14件も成功。ログは `generated/street-comparison-{good,bad}-{physics,render}.log`、同じ経路位置の画像比較は `generated/street-comparison/comparison.png`。移動と描画の自動検査であり、誘導効果の人による比較実験ではない。

## 地図・マーカーを使わない街区改修

比較26はそのまま保存し、通常制作データと新しいGood配布版を改修する。ミニマップ、目的地アイコン、矢印、光の道、輪郭強調、誘導用の点列、ゲーム内の解説は加えない。既存のコインも本線上の点列から寄り道・座席脇などの報酬へ移す。ショップ本来のコーヒー看板は一箇所に残し、分岐・出口への複製を取り除く。

### 街区ごとの問題と改修

| 場所 | 旧版の問題 | 改修 |
|---|---|---|
| 入口 | 庇が空を塞ぎ、道路からカフェへの広がりが弱い。口元の床が急に広がる | 頭上の庇を外して空を見せ、入口の裾に実際の床を追加。カフェの開けた面を次の場所として見せる |
| カフェ | 水路の輪郭が塗装頼み。コインが水路中央へ誘う | 両岸に立体の石の笠木と端部支柱。カフェ全体を石畳にし、着地面と縁の段差を見せる。コインを水路から外す |
| 店脇 | 二つの似た庇と看板が同格で、場所の役割を判別しにくい | 左は木の低いサービス庇、右は高く開いたアーケード。両側とも通れ、同じ裏庭へつながる |
| 裏庭 | 階段が画面外になりやすく、歯車が孤立している | 入口からの構図を横へ少し平行移動し、角度を振らず階段を映す。歯車と扉を支持柱・軸で接続し、階段前に建築的な踊り場を作る |
| 屋上 | 次の屋上が画面左端に寄る。別方向の遠景時計と出口の看板が競合する | カメラを少し左へ寄せ、着地縁に石の断面を付ける。遠景時計を目的地脇へ移し、出口の先にも実際に歩ける通路を接続 |
| 全体 | 似た窓列・床・庇が繰り返され、背景の細部が主役と競合する | カフェは石、裏庭は庭園舗装、屋上は陶板。色だけでなく空間と用途を変える。遠景は窓を省略し、近景と時計塔を読みやすくする |

新街区の静的ジオメトリは24バッチ・146777ポリゴン。旧版28バッチ・253771ポリゴンから削減。タイトルの空・光、近い視点、画角58度、CC0部品を維持し、動的な照明や誘導エフェクトは増やさない。

描画による見直し：店脇の奥側にも門と梁を置いた初案は、裏庭に出たとき手前の梁が大きく映って見通しを遮っていた。衝突判定を持たない装飾は物理レイ検査だけでは拾えないため、実際の連続描画を見て奥の門と梁を撤去した。入口の枠は残し、出口側を空と階段へ開く。

## CC0素材による近景の外観改修（配布29）

AAA作品を品質の目標として、今回は建物の組み立て・近景の材質・街の足元を作り直した。AAA作品と同等の総合品質を達成したという報告ではない。キャラクターを含む全体の造形、物の接地感、角の処理、照明・反射、移動中の画面安定、全景の密度を引き続き評価する必要がある。

### 使用素材と組み立て

- 建築は同梱済みの [Quaternius Downtown City MegaKit](https://quaternius.com/packs/downtowncitymegakit.html) のCC0無料版。上階窓、一階の店舗窓、柱、軒飾り、扉と枠、室外機、ボラード、排水部品をネイティブの寸法で組み合わせる。公式の315モデルすべてを導入したのではなく、同梱の無料部品を使用する。元のCC0許諾文は `Assets/Models/Sunrise/Cafe/Quaternius-License.txt`。
- 家具・壁灯・樹木は同梱のKenney CC0モデル。小さな植木だけでなく、遊べる面の外側に大きい樹木を置き、カメラの前やジャンプ先を塞がない配置にする。
- 床は [Poly Haven / Pavement 05](https://polyhaven.com/a/pavement_05)、作者Jan Burghardt。公式の1K PNG色・DirectX法線をそのまま導入し、3.4mの実寸タイルで使用する。
- 備品は [Poly Haven / Wooden Crate 02](https://polyhaven.com/a/wooden_crate_02)、モデリングJames Ray Cock・グラフィックJurita Burger。元のglTF、バイナリとJPG依存ファイルを保存し、ゲーム用には公式の1K PNG色・法線を使う。箱本体と蓋のノード移動を合成して静的メッシュへ変換。金属・粗さ・AOのパック画像は元データとして保存するが、実行時の材質は色・法線と一定の粗さで近似しており、全チャンネルを実装したとは扱わない。
- Poly Havenの素材は[公式ライセンス](https://polyhaven.com/license)でCC0と確認。出所、作者、URL、取得ファイルのMD5/SHA-256を `Assets/Textures/StreetJourney/PolyHaven/{Source,Crate-Source}.json` へ保存。元画像・元モデルのバイト列は変更しない。階段・床・庇・基礎などの支持形状は本作の構造用ジオメトリ。

### 修正した問題

窓のガラスは壁面の約0.16m奥にあるが、旧版の箱の表面は約0.15m奥だったため、壁がガラスを覆っていた。調査当初は向きを疑ったが、法線と実描画を確認し、元の外向き面を維持して構造壁を約0.325m奥へ移すことで解決した。窓の裏側を見せる向きへの反転は最終版に採用していない。

基壇、階ごとの帯、軒飾り、扉、一階の店舗窓を付け、壁面を単なる大きな箱に見せない構成へ変更。カフェは暖色、隣の店舗はセージ色、入口の片側は冷色に寄せ、同じキットの中で場所を区別する。部品のテクスチャ付き色係数がバッチ作成時に白へ消される問題も修正し、元の材質の色と建物ごとの色味を保持する。

平らな庇を傾斜と支持金物のある形にし、マンホール・排水口・壁灯・室外機・木箱で用途と実寸感を補う。木箱には衝突面も追加した。動線の上へ小物を均等に散布せず、カフェのサービス脇などにまとめる。

街区の下には落下復帰面より低い非歩行用の地面を置き、床・建物の基礎をそこへつなげた。元の薄い床の衝突面やジャンプの隙間は維持する。遠景に見える地面へ降りて進めるという意味ではない。

石畳と使用する建築テクスチャはミップマップを有効にして、遠景の細部のちらつきを抑える。色画像と法線画像は異なるガンマ設定で読み込み、1Kを上限にする。元の画像は書き換えない。ゲーム本体・Engine・SceneRuntime・共有の配布ビルド処理は変更せず、ゲーム素材と街区生成処理の範囲で実装する。

制作処理は `scripts/StreetArchitecture.py` と `scripts/AuthorStreetJourney.py`。静的ジオメトリは33バッチ・116343ポリゴンで、配布28の146777ポリゴンより約21%少ない。見える外壁だけに部品を配置したため、近景の部品を増やしてもジオメトリの総数は減った。材質バッチは24から33へ増えており、ポリゴン削減だけを描画負荷の改善と同一視しない。

## 構造と装飾による進路の読みやすさ（配布30）

今回の対象はマップの構造と静的な装飾だけ。移動、ジャンプ、攻撃、敵、回復、復帰地点、仕掛け、カメラ、照明、タイトルの設定は配布29と同一。修辞技法を別々の実験ステージにせず、一つの正規の街区の構成に応用する。地図、マーカー、点列、矢印、ゲーム内の説明や技法名は追加しない。

### 調査と修辞技法の扱い

[任天堂の開発者インタビュー](https://www.nintendo.com/jp/interview/arzga/02.html)では、建物や障害物の高低差、画面内に次の場所を見せること、カメラとマップを一緒に調整することを確認した。今回カメラは既存の穏やかな設定を保ち、その画面から分かる開口と足場を作る。

[Brendon ChungのGDC講演公開概要](https://www.gdcvault.com/play/1022117/level-design-in-a-day)と[公開スライド](https://media.gdcvault.com/gdc2015/presentations/chung_brendon_wayfindingandstorytelling.pdf)は、建築で情報を伝え、通路・部屋・扉・階段を扱う資料として確認した。動画全編の視聴とは扱わない。[The Level Design BookのWayfinding](https://book.leveldesignbook.com/process/blockout/wayfinding)では、地区・境界・分岐・ランドマークの組み合わせ、反復、空間の用途からの推測を確認した。探索して本線を避ける行動も尊重するため、二つの通路と合流を保つ。同書の確率表は非科学的な目安なので効果の数値根拠には使わない。

修辞の定義は大学の資料で確認した。以下の空間への対応は**本作の設計上の翻案**であり、文学上の技法がゲームの誘導効果を保証するという主張ではない。

| 技法と資料 | 文学での働き | 今回の空間への応用 |
|---|---|---|
| 対比法：[BYU / antithesis](https://rhetoric.byu.edu/Figures/A/antithesis.htm) | 対照的な語や考えを並べる | 建物に囲まれた入口から、空と広い着地面のあるカフェへ出る。分岐では木床と低い庇のサービス路地、石床と空の見える本線を並べ、用途から区別できるようにする |
| 反復、特に文頭反復：[Oregon State University / Anaphora](https://liberalarts.oregonstate.edu/wlf/what-anaphora) | 文や節の始めに同じ表現を置く | 各空間の入口に、淡い石の基部と濃い笠木を持つ建築の端部を置く。入口、カフェ両岸、アーケード、裏庭入口、屋上両岸で「ここが空間のつながり」と読み取るための同じ文法を使う。床上に点を並べる方法ではない |
| 漸層法：[BYU / climax](https://rhetoric.byu.edu/Figures/C/climax.htm) | 表現を重要性の増す順に並べる（狭義には語句を受け継ぐ連鎖も指す） | 今回は広義の段階的な構成を参考にする。地上のテラス、囲まれた裏庭、実際に上る階段、空が開ける屋上という順序を、階段に沿って上がる側壁と屋上の余白で強める。単に小物を大きい順に置いたものではない |

### 実際の変更

1. 入口道路を8mから9mへ広げ、東側の建物の終端を3m手前へ後退。曲がる先が早い段階で開ける。
2. カフェ手前の裾を奥行き3mから7mへ広げ、建物の角で即座に進路を決める必要を減らす。
3. 入口の終わりに低い石組みの端部を置き、路地からテラスへの切り替わりを立体で示す。頭上は塞がない。
4. カフェの両岸に同じ石組みを配置。対岸も実際に歩ける同種の床だと対応づける。支柱間の有効幅は6m以上を残す。
5. 東側カフェの座席を外周の二つのまとまりへ移す。着地面と分岐までの見通しに家具を散らさない。
6. 左のサービス路地を面全体の木床と荷捌き台・木箱で構成。右の石造アーケードとは、色だけでなく床材・天井・用途が違う場所にする。
7. 荷物は壁際へ集約し、左の寄り道を通り抜けられる幅を残す。寄り道の報酬と本線への合流は維持する。
8. 二つの通路が出る裏庭に共通の開口と低い側壁を追加。どちらから来ても同じ部屋へ着いたことを読み取れるようにする。
9. 裏庭中央の植え込みを縮め、歯車付近の植木を端へ移す。階段と機械の間の関係を見通せる余白を残す。
10. 十二段の階段の両脇に、段の高さに沿って上がる低い側壁と笠木を作る。通路幅4m以上を保ち、上り口から実際に上る方向を読み取れる形にする。
11. 屋上の両岸にもカフェと共通の石組みを使い、跳び移りの関係を再提示。庇と座席を外側へ寄せて隣の足場と出口を隠さない。

追加物は既存CC0部品と構造用ジオメトリを静的バッチへ焼き込む。34バッチ・126895ポリゴン。配布29より10552ポリゴン増えるため、軽くなったという報告ではなく、既存の上限34バッチ・170000ポリゴン内に収めた改修である。
